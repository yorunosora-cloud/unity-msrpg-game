# 22. 전투 시스템 확장

> **상태**: 사용자와 대화로 방향·버프 규칙·일반 적 기반까지 확정(2026-11-21), **구현 미착수(설계만)**. 미결은 §7의 보스 면역 수준과 수치 튜닝뿐.
> **성격**: 캐릭터 문서(`Assets/_Game/Resources/Data/Characters/`)에 쌓인 스킬·폼체인지·패시브 설계를 **런타임이 실제로
> 실행할 수 있게** 전투 시스템을 확장하는 설계. 18(캐릭터 스키마)·03(시너지)의 데이터 설계를 재사용하고, 그 둘이 전제한
> 런타임 기반(입력·슬롯·상태 효과·폼)을 이 문서가 맡는다.

---

## 배경

캐릭터 설계(물리 21명, 화학 5원소 중 3개)가 진행되면서 현재 코드가 표현하지 못하는 요소가 계속 쌓였다(캐릭터 문서의
"확인 필요" 절). 2026-11-21 현황 점검 결과 **설계도(키 체계 Q/R/T/F/V/G, 캐릭터별 평타, 강점 태그, 텔레그래프)와 코드가
다르다** — 설계는 있으나 구현은 되지 않은 상태다.

핵심 원칙: **"캐릭터 문서가 기준이다. 코드를 문서에 맞춘다."**

---

## 1. 목표 / 완료 정의

1. 키 입력이 캐릭터 문서 체계(`Q`=기본기, `R/T/F/V/G/B`=슬롯 1~6, `Z/X`=폼 전환)로 동작한다.
2. 파티는 **최대 5명**이고 `1~5` 키로 전환한다(활성 1명 조작 방식은 유지).
3. 기본기(Q)가 캐릭터·폼별로 다른 형태·사거리·각도·쿨타임을 갖는다.
4. 스킬이 부채꼴 외에 **직선·원형** 범위를 쓰고, 도트·둔화·스턴·피해감소·보호막·넉백·견인·스택 같은 **상태 효과**를 낸다.
5. **폼체인지** 캐릭터가 동작한다(폼별 스탯·role·스킬, 폼 전환 규칙 4유형, 자동 복귀).
6. **패시브**가 트리거(OnHit/OnHitTaken/OnFormChange 등)로 발동한다.
7. **아군 대상 스킬**이 "아군=파티 구성원" 규칙으로 동작한다(§4-5).
8. 단계별로 EditMode 테스트가 통과한다(각 단계 완료 기준).

## 4. 아키텍처

### 4-1. 입력 · 슬롯 · 파티 (P1)

**키 맵**
| 키 | 동작 | 슬롯 |
|---|---|---|
| `Q` | 기본기 | 0 |
| `R` `T` `F` `V` `G` `B` | 스킬 | 1 `R` / 2 `T` / 3 `F` / 4 `V` / 5 `G` / 6 `B` |
| `Z` `X` | 폼 전환 | 전환 키 0 / 1 |
| `1`~`5` | 파티 전환 | — |

- `B`는 7번째 슬롯(글루온·포르테·세미라 등 7슬롯 캐릭터용). 기존 이동·UI 키(`WASD`/`Space`/`E`/`C`/`Tab`/`M`/`F1`/`Esc`)와
  충돌이 없는지 P1에서 전수 확인한다.
- **슬롯 해석 변경**: `CharacterDef.skills[]`의 인덱스=키 방식을 폐기하고 각 `SkillDef`가 `slot`(0~6)과 `formReq`를 가진다.
  런타임은 "현재 폼에서 슬롯 s를 채우는 스킬" = `slot==s`이고 (`formReq`가 비었거나 현재 폼과 같은) 첫 스킬로 찾는다.
- 파티: `Party`/`PartyController`/`PartyHud`를 5명으로 확장. 기존 규칙(기절 시 자동 교체, 전멸 시 `PlayerDeath`) 유지.

### 4-2. SkillDef 확장 (P1~P2)

18번 설계(`skillType`/`strengthTags`/`formReq`/`unlockCond`/`skillMotion`)에 이 문서가 다음을 더한다.

```csharp
public enum SkillShape { Cone, Line, Circle }
public enum SkillKind  { Active, Passive, FormChange }

// SkillDef에 추가되는 필드 (기존 필드는 유지·호환)
public int       slot;            // 0~6 (Q/R/T/F/V/G/B)
public SkillKind skillType;       // Active / Passive / FormChange
public string    formReq;         // 비면 모든 폼
public SkillShape shape;          // Cone(기본, halfAngle) / Line(lineWidth) / Circle(radius)
public float     lineWidth, radius;
public SkillEffectEntry[] effects;   // §4-3. 비어 있으면 기존 effectKind 경로(호환)
public PassiveSpec passive;          // skillType == Passive 일 때 (§4-7)
public FormChangeSpec formChange;    // skillType == FormChange 일 때 (§4-6)
public string factNoteKo, gameNoteKo; // UI용 "사실 기반 / 게임적 설정" 문구(캐릭터 문서의 구분 표기를 그대로 담는다)
```

- `factNoteKo`/`gameNoteKo`: 스킬 정보 UI에 "게임적 설정" 문구를 표시하기 위한 필드(과학 사실과 게임용 해석을 구분해 알린다는
  원칙의 구현 지점).
- `halfAngle`/`range`는 Cone 전용으로 유지. Line은 `range`+`lineWidth`, Circle은 `radius`(자신 중심).

### 4-3. 효과 목록 `SkillEffectEntry` (P2)

효과를 열거형 4종에서 **조합 가능한 목록**으로 일반화한다. 한 스킬이 피해 + 둔화처럼 여러 효과를 낸다.

```csharp
public enum SkillEffectType {
    Damage,          // atk × multiplier
    Heal,            // maxHp × percent
    Shield,          // 보호막(maxHp 또는 고정 비율), duration
    StatBuff,        // atk/def/spd/mp 배율, duration
    StatDebuff,      // 대상 atk/def/명중 배율, duration
    Dot,             // atk × 비율 / 초, duration
    Slow,            // 이동속도 배율, duration
    Stun,            // duration
    DamageTakenMult, // 받는 피해 배율(피해 감소·증가), duration
    Knockback,       // 거리 (적 또는 자신)
    Pull,            // 중심으로 견인
    Mark,            // markId, duration (03 시너지)
    SelfDamage,      // 자신 maxHp 비율 소모
    RestoreMp,       // 대상 MP 회복
    Cleanse,         // 상태 이상 해제
}

[Serializable] public struct SkillEffectEntry {
    public SkillEffectType type;
    public TargetScope     target;   // §4-5
    public float           value;    // 배율/비율/거리
    public float           duration;
    public int             maxStacks;      // 스택형(산화·연쇄화 등)
    public int             targetCap;      // "최대 N명" (0=제한 없음)
}
```

- **호환**: `effects`가 비어 있으면 기존 `effectKind` 경로(Strike/Aoe/HealBuff/Mark)로 동작한다. 기존 시드 캐릭터·테스트(`SkillTests` 등)가
  그대로 통과해야 한다.
- **마일스톤(Lv.3) = 효과별 교체값 필드(확정 2026-11-21).** 캐릭터 문서의 마일스톤은 전부 수치 교체형("스택당 −3%→−4%", "지속 2초→3초", "+20%→+30%", "최대 +30%→+40%")이라
  항목마다 교체값을 둔다. **0이면 교체 없음**, `레벨 ≥ SkillDef.milestoneLevel`(기본 3)이면 교체값을 쓴다. 기존 보너스 필드 5개(`milestoneRangeBonus` 등)는 기존 4종 경로 호환용으로 유지.
  - `SkillEffectEntry`: `milestoneValue`, `milestoneDuration`
  - `StackSpec`(§4-7): `milestonePerStackValue`, `milestoneMaxStacks`
  - `PassiveModifierSpec`(§4-7): `milestoneValue`, `milestoneCap` (공식형 상한 예: 회전축 +30%→+40%)
  - 레벨 스케일링(`SkillScaling.ScaleEffectValue`)은 교체값 적용 **후** 위력 곡선을 곱한다.
- **시드 스킬(확정):** 기존 시드 10종은 이전하지 않는다(`effects` 비어 있는 호환 경로 유지). 18번 CSV 임포터(`CharacterSeedSetup` 대체)가 만드는 신규 에셋부터 `effects`를 쓰고, 임포터 완성 시 시드는 자연 소멸한다.

### 4-4. 상태 효과 `StatusHolder` (P2)

시간이 있는 효과(도트·둔화·스턴·버프·피해감소·보호막·스택·표식)를 **한 곳에서 관리하는 순수 C# 컨테이너**.

```csharp
public class StatusHolder {
    public void Apply(StatusEffect e);          // 스택/갱신 규칙 포함
    public void Tick(float dt, bool isActive, Action<int> dealDot);
    // isActive == false: 이로운 효과(버프) 타이머 일시정지, 해로운 효과(디버프·도트)는 실시간 진행
    public float Mult(StatKind k);              // 피해/받는 피해/이속/공격력 등 곱연산 합성
    public int   Stacks(string id);
    public bool  IsStunned { get; }
}
```

- `CombatCharacter`(파티 5명 전원)와 `Enemy`(보스 포함) **양쪽에 부착**한다. 기존 `_atkBuffMult` 단일 필드는 `StatusHolder`로 흡수한다.
- **시간 규칙**은 §4-5-1을 따른다: 이로운 효과(버프)는 그 캐릭터가 활성일 때만 흐르고, 해로운 효과는 실시간으로 흐른다.
  각 `StatusEffect`는 `isBeneficial`(이로운지)과 `pendingUntilActive`(예약 상태)를 가진다.
- 순수 C#으로 두어 `CombatCharacter`처럼 EditMode 테스트가 가능하게 한다(기존 원칙 유지: 로직은 순수 클래스, Unity 의존은 Executor).

**피해 파이프라인**(P2에서 정립, P5에서 태그 배율 삽입)
```
atk' = caster.Atk × skillMult × statusMult(공격자) × tagMult(P5)
dmg  = CombatMath.ComputeDamage(atk', def, isWeakness) × statusMult(받는 피해)
```
`CombatMath.ComputeDamage` 공식 자체는 변경하지 않는다.

### 4-5. 대상 범위 `TargetScope` — 아군 재정의 (P2)

월드에는 활성 캐릭터만 존재하므로 **아군 대상 = 대기 중인 파티원 + 자신**으로 재정의한다(2026-11-21 확정).

```csharp
public enum TargetScope {
    EnemyArea,      // 스킬 형태(Cone/Line/Circle) 안의 적
    Self,           // 시전자(활성 캐릭터)
    Bench,          // 대기 중인 아군(기절 제외). 단일 대상(targetCap=1) 지원 스킬은 대기 아군이 없으면 자신에게 적용(fallbackSelf)
    SelfAndBench,   // 자신 + 대기 아군 (targetCap = 자신 포함 최대 인원)
}
```

- 효과는 항목마다 대상 범위를 가진다(예: "피해 + 자신 이동속도 버프" = Damage(EnemyArea) + StatBuff(Self)).
- **아군만 대상인 스킬은 반경 개념이 없다.** 대기 아군은 월드에 없으므로 `radius` 값은 의미가 없고, 캐릭터 문서의 해당 스킬에서 반경
  표기를 제거한다. 적에게도 효과가 있는 스킬(피해 + 아군 버프)은 **적 대상 부분에만** 형태·반경을 유지한다.
- **"범위 내 아군 N명"** (캐릭터 문서 표기)은 `SelfAndBench` + `targetCap=N`으로 재정의한다. **N은 자신을 포함한 인원 수**이다
  (예: "자신 포함 최대 4명" = 자신 + 대기 아군 3명). 대기 아군이 N−1보다 많으면 **살아 있는 사람 중 HP 비율이 낮은 순**으로 고른다
  (기절자 제외). 대기 아군이 없으면 자신에게만 적용된다.
- **캐릭터 문서 재정의(2026-11-21 완료)**: 아군 표기가 있던 6개 문서(물리: 반도체·시간·자기장, 화학: 산소·수소·탄소)의 "범위 내 아군 …" 문구와 반경
  표기를 이 규칙으로 고쳤다. 아군 전용 스킬 7개는 반경을 제거했고, 적에게도 효과가 있는 스킬(구형 케이지·산소 공급·LED·다이오드)은 반경·형태를
  **적 대상 부분에만** 남겼다. 신규 캐릭터는 처음부터 이 규칙으로 쓴다. 해석이 들어간 두 곳: 마그놀 [2/T] 전자기력은 "파티에 포함된 동안 상시 적용되는
  패시브(`PartyPresence`)"로, 카르보나 내포는 "대기 아군 1명(없으면 자신)"으로 정의했다.

#### 4-5-1. 버프 시간 규칙 (전환 기점)

| 상황 | 규칙 |
|---|---|
| 활성 본인에게 버프 | 시전 즉시 적용·타이머 시작(활성이므로 즉시 흐름) |
| 대기 캐릭터에게 버프 | **예약 상태**로 보관. 그 캐릭터가 **활성이 되는 순간 타이머 시작**(전환 기점) |
| 버프 타이머 | **그 캐릭터가 활성일 때만** 흐른다. 활성에서 대기로 바뀌면 남은 시간이 **일시정지**, 다시 활성이 되면 재개 |
| 폼 자동 복귀 타이머 | 버프와 같은 원칙(활성일 때만 흐름). 폼은 대기 중에도 **유지** |
| 같은 버프 중복 | **갱신**(더 강한 수치, 더 긴 시간 중 큰 쪽). 다른 종류의 버프는 **공존** |
| 즉발 효과(회복·MP 회복·정화) | **시전 즉시** 대기 캐릭터에 적용(전환 기점 불필요) |
| 예약 버프 수명 | 실시간 **60초** 후 소멸(튜닝 값). 모험·던전 이탈, 해당 캐릭터 기절 시 소멸 |
| 해로운 효과(디버프·도트·둔화) | **실시간** 경과(대기 중에도 소진). 스턴은 걸린 캐릭터에게만 붙고 교체해 들어온 캐릭터에는 영향 없음 |
| 대기 캐릭터의 쿨타임·MP | 쿨타임과 MP 자연회복은 **대기 중에도 진행**(현재 코드는 대기 시 멈춤 — 변경 지점) |
| 캐릭터 전환 쿨타임 | **1초**(기절로 인한 자동 교체는 쿨타임 없음) |
| 기절 캐릭터 | 아군 대상 선택에서 제외, 걸려 있던 버프는 소멸 |

- 효과는 **캐릭터별로 각각** 관리한다(캐릭터마다 자신의 `StatusHolder`). 한 캐릭터가 건 버프를 여러 대기 캐릭터가 각자의 타이머로 가진다.
- 적의 공격은 **활성 캐릭터에게만** 간다(대기 캐릭터는 공격받지 않는다).
- 전환 시 이벤트(`OnSwitchIn`/`OnSwitchOut`)를 발행해 예약 버프 시작·폼 타이머 재개·UI 갱신을 처리한다. 패시브 트리거(§4-7)에도 이 이벤트를 추가한다.
- UI: 파티 HUD의 슬롯마다 **현재 버프 아이콘**(활성 시 남은 시간)과 **예약 상태 표시**(대기 중 점선/흐림)를 보여 준다(P2 HUD 요구사항, 표현은 구현 때 확정).

- `CombatCharacter`가 현재 폼을 보유하고, 스탯·스킬 해석(`formReq`)·HUD 색을 폼 기준으로 바꾼다. 폼 전환 시 **현재 HP%는 유지**한다.
- **폼 전환 규칙 4유형**은 `FormChangeSpec`으로 데이터화한다. 캐릭터 문서에 이미 나온 유형을 모두 포함한다.

| 유형 | 의미 | 예 |
|---|---|---|
| Manual | 전환 키로 지정 폼으로 | 루미에르 이중성, 세미라 도핑 |
| Sequential | 키를 누를 때마다 다음 단계 폼으로 | 하이드리아 중성자 포획 |
| Hub | 허브 폼에서 키별로 분기, 재입력 시 허브 복귀 | 옥시아 해리/결합 |
| StateBased | 누른 순간 캐릭터 상태(피격·이동·정지 등)로 폼 결정, 우선순위 | 카르보나 동소 변환 |
| (옵션) AutoRevert | 일정 시간 후 지정 폼으로 자동 복귀 | 삼중수소 12.3초, 원자 산소 8초, 오존 10초 |
| (옵션) 자동 전환 | 이동 속도·점프 등으로 폼 판정 | 에네르기아 |

- `FormChangeSpec`: `fromForms[]`, `toForm`, `stateRules[]`(조건·우선순위), `revertAfterSeconds`, `revertToForm`, `pressAgainReverts`,
  `keyIndex`(Z=0, X=1).
- 자동 전환형(에네르기아 등 속도·점프 판정)은 `FormAutoRule`로 별도 정의한다 — 상세는 아래 §4-6-1(2026-11-21 확정).

#### 4-6-1. 폼 규칙 (2026-11-21 확정)

**① 표현 방식 = 데이터화 + 특수 훅.** 현재 캐릭터 문서의 폼 규칙 7유형(수동 토글·순차·허브·상태연동·자동 3종)이 전부 아래 두 구조로 표현된다.
예외가 생기면 `FormHook` 코드 훅(`ICustomFormRule`)을 추가한다(데이터로 안 되는 경우에만).

```csharp
public enum FormChangeMode { Toggle, Sequential, Hub, StateBased }
public enum FormStateCond  { Always, RecentlyHit /*초 파라미터*/, Moving, Idle }

[Serializable] public struct FormStateRule { public FormStateCond cond; public float param; public string toForm; public int priority; }

[Serializable] public class FormChangeSpec {          // SkillDef(skillType=FormChange)에 부착
    public int            keyIndex;            // 0=Z, 1=X
    public FormChangeMode mode;
    public string[]       fromForms;           // 이 스킬이 쓰일 수 있는 폼(비면 모든 폼)
    public string         toForm;              // Toggle/Hub: 목적 폼
    public string[]       sequence;            // Sequential: 순서(마지막 폼에서는 사용 불가)
    public FormStateRule[] stateRules;         // StateBased: 누른 순간 상태로 결정, priority 높은 것 우선
    public float          revertAfterSeconds;  // 0=자동 복귀 없음
    public string         revertToForm;
    public bool           pressAgainReverts;   // 목적 폼에서 같은 키 재입력 → 기본 폼 복귀(mp 소모 없음, 쿨타임만)
}

public enum FormAutoCond { SpeedRatioAtLeast, SpeedRatioBelow, JumpApex, JumpFalling, IdleFor, MovingFor, HitTargetStat }

[Serializable] public struct FormAutoRule {           // CharacterDef.autoRules[]
    public FormAutoCond cond;
    public float  param;            // 비율/수직속도 임계/지속 초
    public string statKey;          // HitTargetStat: 적 속성 키("temp")
    public int    statCompare;      // HitTargetStat: ≥ / <
    public float  statThreshold;    // 예: 50
    public int    consecutive;      // HitTargetStat: 연속 타격 횟수(예: 3)
    public string toForm;
    public int    priority;         // 높을수록 우선
}
```

| 캐릭터 | 구조 |
|---|---|
| 루미에르·세미라 | Toggle (Z), 양방향 |
| 수소 | Sequential(Protium→Deuterium→Tritium), Tritium `revertAfterSeconds=12.3` → Protium |
| 산소 | Hub(O₂): Z=원자 산소(8초 복귀), X=오존(10초 복귀), `pressAgainReverts` |
| 탄소 | StateBased(Z): RecentlyHit(3초)→다이아몬드(우선 3) > Moving→그래핀(2) > Always→풀러렌(1), 비흑연에서 재입력=흑연 복귀 |
| 에네르기아 | autoRules: SpeedRatioAtLeast 0.7→운동(1), SpeedRatioBelow 0.4→위치(1), JumpApex(\|vY\|<1.5)→위치(2), JumpFalling(vY<−1.5)→운동(3). 해당 없으면 현재 폼 유지 = 히스테리시스 |
| 마시오&이네르셔 | autoRules: IdleFor 2→마시오, MovingFor 2→이네르셔 |
| 테르미아 | autoRules: HitTargetStat(temp ≥ 50, 연속 3)→고온, (temp < 50, 연속 3)→저온 |

**② 이월 규칙(폼이 바뀔 때):** HP·MP는 **비율로 이월**(`새 현재 = 새 최대 × 이전 현재/이전 최대`, HP는 이전에 생존했으면 최소 1). 스킬 쿨타임은 **스킬 단위로 유지**(폼이 바뀌어도 초기화 없음, 폼 전환 스킬 자신의 쿨타임만 따로 적용). 버프·디버프 등 **상태 효과도 모두 유지**.
**③ 평가 시점(자동 전환):** **활성 캐릭터일 때만** 평가하고, 활성이 되는 순간(`OnSwitchIn`) 누적 카운터(정지/이동 지속, 연속 타격)를 **0으로 초기화**한다. 대기 중에는 폼 유지. 자동 복귀 타이머도 활성일 때만 흐르고(버프와 같은 원칙), 폼에 진입할 때 시작한다.
**④ 전환 제한:** **스턴·기절 중에는 Z/X 수동 전환 불가.** 파티 전환 쿨타임(1초)과는 **독립**이다(파티 전환 직후에도 폼 전환 가능). 전환 스킬 자체의 mp·쿨타임은 적용된다(재입력 복귀는 mp 무소모). 자동 전환은 스턴과 무관하게 동작하되 전환 후 최소 유지 시간 `minHoldSeconds = 0.25초`(잠정)로 깜빡임을 막는다.

**⑤ 슬롯 해석 보완(P1 코드 수정 필요):**
- 슬롯 0 해석에서 `skillType == FormChange`인 스킬은 **제외**한다(Q는 기본기만). `Z`/`X`는 `FormChange` 스킬을 `keyIndex`로 찾는다.
- `formReq`는 **쉼표 구분 복수 폼**을 허용한다(예: 수소 중성자 포획 = `"Protium,Deuterium"`).
- `FormChange` 스킬은 `SkillDef.slot = 0`을 유지한다(문서 표기 `[0/Z]`와 일치).

**⑥ 이벤트·기절·복구(잠정):** 폼이 바뀌면 `OnFormChange(from, to, cause)`(cause = Manual/Auto/Revert)를 발행해 패시브(P4)·HUD가 구독한다. 캐릭터가 기절하면 **기본 폼(`isDefault`)으로 되돌린다**(상태 효과 소멸 규칙과 같은 원칙), `RestoreAll`도 기본 폼으로 초기화한다.
**⑦ 의존:** `HitTargetStat` 조건은 적 속성 값(`AttributeProfile.temp`, P5)이 필요하다. P3에서는 조건 종류·연속 카운터 로직·`IEnemyAttributes` 인터페이스만 만들고 값 조회 연결은 P5에서 한다(P3 테스트는 가짜 구현으로 검증).

### 4-7. 패시브 `PassiveSpec` (P4)

**확정(2026-11-21): 3경로 분리.** 캐릭터 문서의 패시브 23개를 분석한 결과 동작 방식이 넷으로 갈려(이벤트 스택형·이벤트 즉발형·상시 수정자·타격 공식)
하나의 구조에 담으면 억지스러워진다. 실행 경로를 셋으로 나눈다.

| 경로 | 트리거 | 하는 일 | 대표 패시브 |
|---|---|---|---|
| **A. 이벤트** | `OnHit` `OnHitTaken` `OnFormChange` `HpBelowPercent` `SelfDebuffed` | `PassiveRunner`가 `CombatCharacter` 이벤트를 구독해 스택·효과(§4-3)를 적용 | 충격량·연쇄화·양자화·운동량·가속도·부도체·콤프턴·반사·작용반작용·영벡터·에너지 보존·동위 원소·산화·회전축(마크) |
| **B. 상시 수정자** | `None` `SelfMoving` `PartyPresence` | 능력치 배율을 상태·공식으로 계속 계산해 `Mult()` 조회에 합성 | 수압(잃은 HP% 비례 피해 감소)·등속운동·정지/운동 관성·고유 시간·전자기력 |
| **C. 타격 공식** | `TargetMoving` 등 | 피해 파이프라인에 `passiveHitMult` 삽입 | 시간 지연(로렌츠)·도플러·일·회전축 거리 보너스 |

```csharp
public enum PassiveTriggerType { None, OnHit, OnHitTaken, OnFormChange, HpBelowPercent, SelfDebuffed, SelfMoving, TargetMoving, PartyPresence }
public enum HitCountMode  { PerAction, PerTarget }                       // 아래 ③
public enum StackDecay    { None, ResetAfterIdle, DecayOneEvery, ConsumeAtCap }
public enum PassiveFormulaId { None, Lorentz, Doppler, RangeWork, AxisDistance }
public enum ModifierSource   { Constant, LostHpPercent, MovingRamp, PartyPresence }

[Serializable] public struct StackSpec {
    public string     stackId;
    public int        maxStacks;
    public float      perStackValue;     // 스택당 수치(배율 증분 등)
    public StackDecay decay;             // 충격량·연쇄화=ResetAfterIdle / 부도체=DecayOneEvery / 양자화=ConsumeAtCap
    public float      decaySeconds;      // 초기화·감소 간격(초)
    public StatKind   stat;              // 스택이 올리는 능력치(SkillPower·DamageTaken·Atk …)
}

[Serializable] public struct PassiveModifierSpec {   // 경로 B
    public ModifierSource source;
    public StatKind       stat;
    public float          value;         // 상수 / 계수(수압 0.005) / 초당 증분(등속 0.03)
    public float          cap;           // 상한(수압 0.30, 등속 0.30)
    public float          decayPerSecond;// MovingRamp: 정지 시 초당 감소(등속 0.05)
    public bool           partyWide;     // PartyPresence: 파티 전원(대기 포함)에 적용
    public float          enemyAuraRadius; // >0이면 적 대상 오라: 활성인 동안 이 반경 안의 모든 적에게 적용(질량 정지 관성 6.0, 잠정)
}

[Serializable] public struct PassiveSpec {
    public PassiveTriggerType trigger;
    public float            value;             // HpBelowPercent 임계(0.4) 또는 공식 파라미터(c=2000)
    public HitCountMode     hitCount;          // OnHit 전용
    public float            internalCooldown;  // 재발동 쿨타임(영벡터 60초)
    public StackSpec        stack;             // 스택형이면 maxStacks>0
    public SkillEffectEntry[] effects;         // 경로 A 발동 효과
    public PassiveModifierSpec[] modifiers;    // 경로 B
    public PassiveFormulaId formula;           // 경로 C
}
```

**확정 규칙**
1. **대기 중 규칙:** 경로 A의 스택·초기화 타이머·내부 쿨타임은 **활성일 때만 흐르고, 대기로 빠져도 스택은 유지**한다(버프 타이머 규칙과 같은 원칙). 경로 B의
   `PartyPresence`는 **활성·대기 무관 상시**(크로노 −15%는 대기 중 쿨타임 진행에도 적용). 나머지 상시 수정자는 활성일 때만 계산한다.
2. **OnHit 횟수(③):** 스택형(충격량·연쇄화·양자화·운동량)은 `PerAction` = **공격 행동 1회당 +1**(범위기가 적 5명을 때려도 1회), 효과형(콤프턴·산화 스택·회전축 마크)은
   `PerTarget` = **적중한 대상마다 1회**. **도트 틱과 패시브가 일으킨 피해(콤프턴 광역·반사 반환)는 OnHit/OnHitTaken 트리거에서 제외**해 무한 연쇄를 막는다.
   기본기·액티브 스킬 모두 OnHit을 일으킨다.
3. **이벤트 페이로드:** `HitInfo { target, attacker, damage, sourceSkill, isBasic, hitPoint, actionId, isProc }`. `OnHitTaken`이 공격자를 알아야 하므로(반사·작용반작용)
   피격 API는 `CombatCharacter.TakeHit(damage, attacker)`로 확장한다(P2의 `TakeHit(int)`는 attacker=null 오버로드로 유지).
4. **신규 대상 범위·필드:** `TargetScope`에 `HitTarget`(적중한 대상, OnHit용)·`Attacker`(공격자, OnHitTaken용)를 추가한다. `SkillEffectEntry`에 `areaRadius`(0=스킬 형태 사용; 콤프턴
   "타격 지점 반경 1.0")를 추가한다. 신규 효과 `Teleport`(변위)를 추가한다. `StatKind`에 `SkillPower`(모든 스킬 위력, 연쇄화)·`HitDamage`(다음 타격 배율, 가속도·양자화)·
   `CooldownRate`(쿨타임 진행 배율, 공격속도·고유 시간)를 추가하고, `StatusEffect`에 `ConsumeOnHit`(다음 타격에서 소모)을 추가한다.
5. **스택 감소 3방식:** 충격량·연쇄화 = `ResetAfterIdle`(N초 무적중 시 전체 초기화), 부도체 = `DecayOneEvery`(N초 무피격 시 1스택씩 감소), 양자화 = `ConsumeAtCap`(최대 도달 후 다음 타격에서 소모).
6. **공식은 `PassiveFormula` 정적 클래스에 모은다(경로 C):** `Lorentz(v, c) = 1/√(1−(v/c)²)`, `Doppler(vRel, c) = √((1+β)/(1−β))`(결과 [0.33, 3.0] 클램프, 범위는 ÷D),
   `RangeWork(range) = 1 + 0.05×range`(최대 +50%), `AxisDistance(dist, max)`(거리 0→0%, 5.0 이상→최대 +30%, 마일스톤 +40%). `c = 2000`은 게임 전역 상수로 `value`에 둔다.
7. **영벡터(변위):** `HpBelowPercent`는 **임계를 위로→아래로 가로지르는 순간 1회 발동(에지 트리거)**, 내부 쿨타임 60초. 효과 = `Teleport(전투 시작 위치)` + `Cleanse`.
   **전투 시작 위치** = "전투 상태"(최근 5초 내 적중·피격 발생)가 **5초 이상 끊겼다가 다시 시작된 지점**의 위치. `CombatAnchor`가 기록한다.
8. **패시브와 폼:** `formReq`가 있는 패시브(질량 정지 관성·운동 관성·콤프턴·반사)는 현재 폼이 맞을 때만 동작한다. 폼 전환 시 스택은 유지하되 폼 불일치 패시브는 비활성이다.
9. **중복:** 같은 패시브 id는 여러 보유자가 있어도 **1회만 적용**(크로노가 파티에 2명 있어도 −15%).
10. **이동·점프 상태 공급:** `SelfMoving`(등속운동)·폼 자동 규칙(§4-6-1)·움직임 판정이 **공통 `CombatMotionState`**(속도 비율·이동 여부·점프 단계)를 읽는다. 플레이어 컨트롤러가 매 프레임 갱신한다.
11. **적 측 스택(산화)·마크(회전축):** 적 `StatusHolder`의 스택 규칙을 쓴다. 적 `Mark`는 `markId`와 지속시간을 가져야 한다(현재 `Enemy.SetMark`는 속성만 보관) — P4에서 확장.
12. **마일스톤:** 패시브의 Lv.3 상향("스택당 −3%→−4%" 등)은 갭 4번(효과 마일스톤 필드)에서 함께 정한다.

### 4-9. 적 측 상태 수용 (P2)

- `Enemy`와 `Boss`에 `StatusHolder`를 부착해 둔화·스턴·도트·피해 증가·표식·스택을 받는다. 스턴/둔화는 `Enemy.Update`의 이동·공격 타이머에 반영한다.
- 넉백·견인은 `Enemy` 위치를 직접 이동시킨다. **보스는 스턴·넉백·견인 면역이 기본**(`BossDef.ccImmune = true`, P2에서 구현, 잠정안). 둔화·도트·받는피해배율은 받는다.
  일반 적은 `Enemy.ccImmune`(기본 false)로 개별 지정. 보스별 예외(특정 보스만 스턴 허용 등)는 보스 설계 때 `ccImmune`을 조정한다.

### 4-10. 일반 적 공격 기반 (트랙 E)

**원칙**: 각 적은 **설계할 때 정한 공격 방식**대로 동작한다. 그 방식을 나중에 **데이터로 채울 수 있도록 기반을 준비**한다(적 설계 자체는 해당
과목·지역 설계 때 진행).

현재: `Enemy`는 접촉 피해(`contactDamage`, `attackInterval`)뿐이고, 텔레그래프(`Telegraph.SpawnCircle` 등)·패턴(`CircleZonePattern`,
`LineBeamPattern`, `ParallelLasersPattern`, `PolygonBarragePattern`)·투사체(`BossProjectile`)는 **보스 전용**
(`BossPatternModule.Execute(BossContext)`)이다. 적 목록 `enemy_catalog.csv`의 `skills` 열은 "이름:타입" 자유 서술(근접/원거리/이동형/장판)이다.

**설계 (보스 패턴 모듈 일반화)**
```csharp
// 보스 전용 BossContext → 공용 AttackContext (Owner = Boss 또는 Enemy)
public class AttackContext {
    public Transform Owner;       // 공격하는 적/보스
    public Transform Target;      // 대상(활성 캐릭터 위치)
    public int       Atk;         // 적 공격력(스케일링 적용)
    public Action<int, StatusEffect[]> DealToPlayer; // 활성 캐릭터에게 피해 + 상태 효과(디버프) 적용
}
public abstract class AttackModule : ScriptableObject {   // 기존 BossPatternModule의 일반화
    public abstract IEnumerator Execute(AttackContext ctx);
}
```
- `BossPatternModule`은 `AttackModule`을 상속하도록 이전한다(기존 보스 패턴 에셋은 호환 유지).
- **신규 모듈 후보**(적 설계에서 쓰이는 공격 유형): 접촉/근접 타격(Melee), 돌진(Charge), 조준 투사체(Projectile), 지면 장판(GroundZone),
  원/부채꼴/직선 범위(기존 Telegraph 재사용), 소환(Summon), 상태 이상 부여(DebuffOnHit), 아군(적끼리) 버프. 유형은 적 설계 때 추가한다.
- **적 정의 `EnemyDef`** (ScriptableObject): 스탯·약점·보상 + `attackModules[]`(공격 모듈 목록과 사용 조건·쿨타임) + 이동 AI 유형
  (`Chase`/`KeepDistance`/`Stationary` 등). `Enemy`는 `EnemyDef`로 구성된다.
- **CSV 구조화**: `enemy_catalog.csv`의 `skills` 열을 `moduleId:param;…`로 구조화한다(자유 서술 "이름:타입"은 기존 행 호환용으로 유지).
  `moduleId`는 `AttackModule` 에셋 id. 17번 설계도의 임포터가 `EnemyDef`를 생성한다.
- **피해 경로**: 모든 공격은 `AttackContext.DealToPlayer`를 통해 **활성 캐릭터**에게만 피해와 상태 효과(§4-4)를 준다. `Telegraph`의 피해 적용 지점을
  이 콜백으로 일원화한다.
- 이 트랙은 **P1~P2와 병행 가능**하나 P2의 `StatusHolder`(디버프 수용)와 `Enemy` 상태 효과 수용에 의존하는 부분이 있어, 모듈 인터페이스(E1)를 먼저 만들고
  상태 효과 부여 모듈(E2)은 P2 이후에 완성한다.

### 4-11. 스킬 정보 UI (확정 2026-11-21)

R&E 패널·도감의 스킬 정보는 세 층으로 구성한다.
1. **수동 설명** — `descKo`를 사람이 쓴 문장 그대로 표시한다(캐릭터 문서의 문장력 보존).
2. **자동 수치 요약** — `effects`/패시브 `StackSpec`·`modifiers`에서 줄을 생성한다. 예: `피해 ×1.5 · 둔화 40% 3초 · 자신+대기 아군 공격력 +15% 5초`. 현재 레벨·마일스톤 교체값을 반영하고
   수치와 설명이 어긋나지 않게 한다. 효과가 없는 기존 4종 스킬은 요약 줄을 생략한다.
3. **설정 박스** — `factNoteKo`("사실 기반")와 `gameNoteKo`("게임적 설정")를 **구분된 두 박스**로 표시한다. 기존 `milestoneDescKo` 안내는 그대로 유지한다.

### 4-12. 전투 상태 초기화 (확정 2026-11-21)

`Party.ResetCombatState()`를 **전투 구역(던전·모험) 진입·이탈, 전멸(`PlayerDeath`), 씬 전환**에서 호출한다.
- **초기화:** 모든 멤버의 `StatusHolder`(예약 버프 포함)·패시브 스택·타이머·`CombatAnchor`, 폼(→ 기본 폼).
- **유지:** HP·MP·스킬 쿨타임(전멸 시에만 기존 `RestoreAll`이 HP·MP·쿨타임을 복구). 쿨타임은 유지해 "이탈-재진입으로 쿨타임 리셋" 꼼수를 막는다.
- 기절한 멤버의 상태 소멸(§4-5-1)과 별개로 동작한다.

### 4-13. 플레이어 측 스턴·둔화 (확정 2026-11-21)

`CombatCharacter.Status`의 효과를 플레이어 입력·이동이 읽는다.
- **스턴:** 활성 캐릭터가 스턴이면 **이동·기본기(Q)·스킬(R~B)·폼 전환(Z/X)·파티 전환(1~5)을 모두 차단**한다. 기절로 인한 자동 교체는 그대로 동작한다.
  - ⚠️ **파급 효과(사용자 확정 사항):** 파티 전환을 막으므로 스턴은 시간이 지나야 풀리는 완전한 잠금이다. 정화(`Cleanse`)를 가진 대기 아군은 스턴 중 시전할 수 없고(스킬 차단),
    영벡터(변위)처럼 **패시브로 발동하는 해제**만 스턴 중에도 동작한다. 따라서 **적 스턴 지속시간은 짧게(권장 상한 1.5초)** 설계하고, 보스는 스턴 면역(§4-9)을 유지한다.
    스턴의 해로움이 크므로 적 설계(E2 `DebuffOnHit`) 때 지속시간·빈도·내성(연속 스턴 시 짧아지는 DR)을 함께 정한다.
- **둔화:** `StatKind.MoveSpeed` 배율을 플레이어 이동속도에 곱한다. **최소 30%를 바닥**으로 둔다(0%로 고정되는 사실상 스턴 방지).
- **공격속도(`CooldownRate`):** 쿨타임 진행 속도 배율(>1이 빠름)로, 파티 `Tick`이 쿨타임 감소량에 곱한다.
- **스턴 중에도 흐르는 것:** 스킬 쿨타임, MP 자연회복, 상태 효과 타이머(스턴 자체 포함). 스턴은 걸린 캐릭터에게만 붙는다(§4-5-1).
- 구현 위치: `PlayerSkills`·`PlayerCombat`·`PartyController`·플레이어 이동이 `PlayerRuntime.Active.Status.IsStunned`를 검사한다.

## 7. 확인 필요 · 후속

- **일반 적의 공격 방식(결정됨)**: 각 적의 설계 시점에 공격 방식을 정하고 `AttackModule` 조합으로 구현한다(§4-10). 17번 설계도의 `skills` 열 자유 서술은
  구조화 대상이다. 적을 실제로 설계하는 과목·지역 단계에서 모듈 유형(돌진·소환·장판 등)을 추가한다.
- **아군 대상 스킬 문서 재정의(완료 2026-11-21)**: 6개 캐릭터 문서를 §4-5 규칙으로 고쳤다. 이후 작성하는 캐릭터는 처음부터 이 규칙을 쓴다.
- **보스의 상태 효과 면역·넉백 면역**: 잠정 결정(스턴·넉백·견인 면역, 나머지 수용 — §4-9). 보스 설계 단계에서 보스별로 재검토.
- **예약 버프 60초 등 수치**는 밸런스 테스트로 조정한다(전환 쿨타임 1초 포함).
- **CSV 저작/임포터(18)와의 순서(확정 2026-11-21)**: **P3(폼) → P4(패시브) → (18번 CSV 임포터 + P5 속성·강점 태그) → P6(시너지)**. 폼·패시브까지 스키마가 확정된 뒤 임포터를 만들어
  CSV 열(`forms`·`formChange`·`autoRules`·`passive` 등)을 한 번에 설계한다. P5는 18번과 같은 내용이라 임포터와 함께 구현한다.
  기존 시드 10종은 이전하지 않고 임포터가 대체한다(§4-3).
- **갭 정리 완료(2026-11-21)**: 폼 §4-6-1 · 패시브 §4-7 · 마일스톤 §4-3 · 스킬 UI §4-11 · 전투 상태 초기화 §4-12 · 플레이어 스턴·둔화 §4-13 · 질량 오라 범위(반경 6.0, §4-7 `enemyAuraRadius`).
- 수치(상태 효과 상한·중첩 규칙·쿨타임)는 밸런스 테스트로 조정한다.
