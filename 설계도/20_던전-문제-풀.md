# 20. 던전 문제 풀

---

## 배경

지금까지 던전 설계 문서(토네이도 평원·판게아 유적·거대 천문대 피라미드·세계 해류 신전)는 모두
"R&E 문제는 `ProblemDef`(스킬 해금용과 동일 구조, `skillId` 비움) 재사용 — 과목=EarthSci로
분류"로 잠정 결정돼 있었다. 이 방식에는 세 가지 문제가 있다.

1. **레벨업 풀 오염** — `ProblemDatabase.RandomByDifficulty()`는 `subject`/`country`를 전혀
   보지 않고 `skillId`가 비어 있고 난이도만 일치하면 전체 풀에서 랜덤 추첨한다. 던전용으로
   만든 문제를 그대로 넣으면 전혀 다른 과목 캐릭터의 레벨업 뽑기에도 섞여 나올 수 있다.
2. **게이트 고정 지정 불가** — 던전 안에 게이트가 여러 개인 경우(세계 해류 신전의 나선
   게이트 3개)를 구분할 방법이 없다. `country`는 자유 입력이라 오타로 풀이 쪼개질 위험도 있다.
3. **난이도 체계가 다름** — 레벨업/스킬 문제는 하/중/상 = EXP 80/200/500 보상 체계지만, 던전
   R&E는 쉬움/보통/어려움 = 개방시간 20/45/90초(또는 던전마다 다른 경감 효과) 체계다. 같은
   enum을 재사용하면 의미가 뒤섞인다.

이 설계도는 위 세 문제를 해결하는 **별도의 던전 문제 풀**(`DungeonProblemDef` 계열)을
정의한다. "R&E"라는 용어는 레벨업/스킬 시스템(`RnEPanel`, Research & Education)에 고유한
이름이므로, 던전 쪽은 그냥 **"던전 문제"**로 부른다.

**범위**: 이번 설계는 데이터 스키마·저장/동기화·관리 탭 저작 UI·조회 API까지만 다룬다. 게이트를
열었을 때의 실제 효과(확정 개방 시간, 나선 속도 경감 등)는 던전마다 다르므로, 각 던전을
코드로 구현할 때(02번 던전/스테이지 템플릿 기반) 개별적으로 만든다.

## 1. 목표 / 완료 정의

- `DungeonProblemDef`를 관리 탭에서 저작 → TitleData에 저장 → 클라이언트가 병합해 로드하는
  한 사이클이 기존 `ProblemDef` 시스템과 동일한 수준으로 동작한다.
- 던전 게이트 스크립트(추후 구현)가 `DungeonProblemDatabase.RandomByGateDifficulty(dungeonId,
  gateId, difficulty)` 한 줄로 해당 게이트·난이도의 문제를 뽑을 수 있다.
- 레벨업/스킬 문제 풀과 완전히 독립적이라, 어느 쪽에서 문제를 추가·삭제해도 다른 쪽에 영향이
  없다.

## 3. 아키텍처

### 데이터 (ScriptableObject)

```csharp
public enum DungeonProblemDifficulty { Easy, Normal, Hard }  // 쉬움/보통/어려움

public class DungeonProblemDef : ScriptableObject
{
    public string id;

    [Header("분류")]
    public Continent subject;   // 과목(대륙) — 관리 탭 트리 그룹핑 기준
    public string    country;   // 국가/세력 — 자유 입력, 폼에만 표시(트리 그룹핑에는 안 씀)
    public string    dungeonId; // 예: "tornado_plains" — DungeonGateCatalog 기준
    public string    gateId;    // 예: "central_totem" / "ekman_gate_nansen"

    public DungeonProblemDifficulty difficulty;
    public ProblemType type;    // 기존 enum 재사용 (MultipleChoice/FreeInput)

    [TextArea(2, 6)]
    public string   prompt;
    public string[] choices = new string[4];
    public int      correctIndex;
    public string[] acceptedAnswers = new string[0];
    [TextArea(1, 4)]
    public string   explanation;
}
```

`subject`/`country`는 레벨업 문제와 동일하게 사람이 직접 선택/입력한다(던전 하나가 보통 과목
하나에 대응하지만, 필드 자체는 `dungeonId`와 독립적으로 둔다). 실제 게이트 매칭은 오직
`dungeonId`+`gateId`+`difficulty`로만 이뤄진다.

### 던전·게이트 카탈로그 (정적 테이블)

`dungeonId`/`gateId`를 자유 입력으로 두면 오타로 풀이 쪼개지므로, 작은 정적 테이블로 관리한다.
새 던전이 설계될 때마다(코드 구현 여부와 무관하게) 이 테이블에 한 줄씩 추가한다.

### 저장 · 동기화 (기존 문제 시스템과 완전히 평행한 구조)

| 기존 (`ProblemDef` 계열) | 신규 (`DungeonProblemDef` 계열) |
|---|---|
| `ProblemDatabase` (Resources 에셋) | `DungeonProblemDatabase` |
| `ProblemDTO` / `ProblemStore` | `DungeonProblemDTO` / `DungeonProblemStore` |
| `ProblemMerge.Apply(seed, store)` | `DungeonProblemMerge.Apply(seed, store)` |
| TitleData 키 `"problems"` | TitleData 키 `"dungeonProblems"` |
| `CloudScript/ProblemAdmin.js`의 `UpsertProblem`/`DeleteProblem` | 같은 파일에 `UpsertDungeonProblem`/`DeleteDungeonProblem` 핸들러 추가. 관리자 키 체크는 `VerifyAdminKey.js` 그대로 재사용 |
| `Backend/ProblemSyncService.cs` | `Backend/DungeonProblemSyncService.cs` |

조회 API (`DungeonProblemDatabase`):

```csharp
public DungeonProblemDef   RandomByGateDifficulty(string dungeonId, string gateId, DungeonProblemDifficulty difficulty);
public DungeonProblemDef[] AllByGate(string dungeonId, string gateId); // 관리 탭 카운트 집계용
public DungeonProblemDef   ById(string id);
public void                Upsert(DungeonProblemDef def);
public void                Remove(string id);
```

`RandomByGateDifficulty`는 `dungeonId`+`gateId`+`difficulty`가 모두 일치하는 후보 중
`UnityEngine.Random.Range`로 1개를 반환한다(`ProblemDatabase.RandomByDifficulty`와 동일
패턴). 완전히 별도 TitleData 키·별도 클래스로 분리했기 때문에 레벨업/스킬 문제 뽑기가 던전
문제를 오염시킬 일이 구조적으로 없다.

### 관리 탭 UI 통합

**트리 구조** (`ProblemTab`에 4번째 최상위 브랜치로 추가, 레벨업 브랜치와 동일하게 과목을
상위 그룹으로 둔다):

```
던전
├─ 지구과학
│   ├─ 토네이도 평원
│   │   └─ 중앙 진입 광장 토템 → 쉬움/보통/어려움 (각 N개)
│   ├─ 판게아 유적
│   │   └─ 지도 토상실 토템 → 쉬움/보통/어려움
│   ├─ 거대 천문대 피라미드
│   │   └─ 별자리 정렬 제단 → 쉬움/보통/어려움
│   └─ 세계 해류 신전
│       ├─ 에크만 나선 게이트 · 난센 → 쉬움/보통/어려움
│       ├─ 에크만 나선 게이트 · 에크만 → 쉬움/보통/어려움
│       └─ 에크만 나선 게이트 · 스토멜 → 쉬움/보통/어려움
├─ 물리 (현재 던전 없음 — 카탈로그에 등록되면 자동 표시)
├─ 화학
├─ 생명과학
├─ 수학
└─ 정보
```

과목 노드는 기존 `_subjects`(6개 배열)를 그대로 순회하고, 그 아래에 `DungeonGateCatalog`에서
`subject`가 일치하는 던전만 나열한다. 국가(`country`)는 트리 그룹핑에는 쓰지 않는다(폼에만
노출).

**`ProblemFormPanel` 변경**:

- `purposeDropdown`에 "던전" 옵션 추가 (레벨업/스킬/던전)
- "던전" 선택 시: `subjectDropdown`(재사용, 필수) + `countryInput`(재사용, 선택 입력) 노출 +
  신규 `dungeonDropdown`(`DungeonGateCatalog`의 던전 목록, 중복 제거) + `gateDropdown`(선택된
  `dungeonId`에 속한 게이트만 필터링) 노출. `skillDropdown`은 숨김.
- `difficultyDropdown`은 구조(3버튼 드롭다운) 그대로, 옵션 텍스트만 상황에 따라
  "하/중/상" ↔ "쉬움/보통/어려움"으로 교체.
- 저장 시 검증: 던전 선택 안 하면 "던전을 선택하세요" 상태 메시지(기존 스킬 미선택 검증과
  동일 패턴).

## 6. 엣지 케이스 / 주의점

| 상황 | 처리 |
|------|------|
| 게이트에 해당 난이도 문제가 0개 | `RandomByGateDifficulty`가 null 반환 → 호출측(게이트 스크립트)이 "문제 준비 안 됨" 처리(각 던전 코드 구현 시 결정) |
| `DungeonGateCatalog`에 없는 조합으로 문제 저장 시도 | 폼이 카탈로그 기반 드롭다운만 제공하므로 자유 입력으로는 발생하지 않음 |
| 과목/국가는 채웠는데 던전 미선택 | 저장 전 검증 — "던전을 선택하세요" (기존 스킬 미선택 검증과 동일 패턴) |
| TitleData 두 키(`problems`/`dungeonProblems`) 동시 존재 | 완전히 독립된 키·클래스라 서로 영향 없음 |
| 새 던전 추가 시 카탈로그 갱신 누락 | `ProblemFormPanel`의 dungeonDropdown이 카탈로그 기반이므로, 누락 시 그 던전은 폼에서 아예 선택 불가 — 실수를 코드가 아니라 UI에서 바로 드러냄 |

## 7. 검증 방법
