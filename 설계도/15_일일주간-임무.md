# 15. 일일·주간 임무 시스템

> `13 출석`이 확립한 `DailyResetHelper`(일일 리셋)를 재사용하고, **주간 리셋**(월요일)
> 로직을 이 설계에서 추가한다. 보상 구조는 **개별 보상 + 완전클리어 보너스**.

---

## 세계관 맥락

- **학사 게시판의 과제(Daily/Weekly Tasks)** — 배움의 전당은 학생에게 매일·매주
  소소한 과제를 내건다. 오늘의 실습(적 처치·미니게임)을 해내면 그날의 지원금이,
  한 주의 과제를 꾸준히 채우면 주간 장학이 지급된다. `13 출석`이 "등원 자체"를
  보상한다면, 임무는 "무엇을 했는가"를 보상해 능동적 플레이를 유도한다.

---

## 1. 목표 / 완료 정의

1. **일일 임무 3종**: 적 처치 / 미니게임 플레이 / 미니게임 점수 도달. 매일 로컬 자정 리셋.
2. **주간 임무 3종**: 적 누적 처치 / 미니게임 누적 플레이 / 미니게임 고득점 도달. 매주 월요일 리셋.
3. **개별 수령**: 각 임무는 목표 달성 시 자기 보상을 개별 수령한다(중복 수령 불가).
4. **완전클리어 보너스**: 그 구분(일일/주간) 임무를 **전부 수령**하면 추가 보너스 1회.
5. **진행도 자동 집계**: 전투 적 사망 → 자동 카운트. 미니게임 → 미니게임 시스템이
   `MissionService.Report(...)`를 호출해 카운트(*미니게임 문서 참고*).
6. **주기 리셋**: 일일은 날짜 변경, 주간은 월요일 주 키 변경 시 진행도·수령상태 초기화.
7. **저장·복원**: 진행도·수령상태·마지막 리셋일/주 키가 PlayFab에 저장되어 유지된다.
8. **진입**: 계정·출석 버튼 옆 상시 버튼으로 `MissionPanel`(일일/주간 탭) 열람.

### 확정 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| 1 | 보상 = **개별 보상 + 완전클리어 보너스**. 활동 점수 게이지 아님 | 게이지 누적 UI가 없어 구현이 단순. 개별 수령 + 전부 완료 보너스로 목표 동기 유지 |
| 2 | 목표 타입 = **적 처치 · 미니게임 플레이 · 미니게임 점수**. 문제풀이·가챠 등은 enum 예약만 | 사용자 선정. 학습(문제)·가챠는 이번 임무 목표에서 제외하되 확장 여지는 남김 |
| 3 | **적 처치 목표는 `적 리스트` 문서의 권장레벨을 참조해 플레이어 레벨대에 맞게 배정** | 진행에 따라 목표가 진부해지지 않게. 적 리스트 문서(대륙·국가·위치·이름·권장레벨·스킬) 확정 후 필터 적용 |
| 4 | **미니게임 목표의 룰·점수 기준은 `미니게임` 문서에 위임**. 여기선 report 훅과 목표 타입만 정의 | 미니게임 미구현. 미니게임 시스템이 생기면 `Report` 한 줄 호출로 자동 연동 |
| 5 | 주간 리셋 = **월요일 00:00 로컬**, 주 키 = 그 주 월요일 날짜 `"yyyy-MM-dd"` | ISO 주 계산 회피, `DailyResetHelper`와 동일한 "날짜 문자열 비교" 정책. 클라이언트 권위(12·13과 동일) |
| 6 | 일일·주간 리셋 유틸을 **`DailyResetHelper`에 주간 메서드 추가**로 통합 | `13`이 만든 리셋 유틸을 canonical로 유지, 파일 분산 방지 |
| 7 | 미니게임 **점수 목표**는 진행도를 **합산이 아니라 최댓값**(`max`)으로 갱신 | "특정 점수 도달"은 누적이 아니라 최고 기록이 기준이므로 |
| 8 | 목표 `contextId`로 대상 지정. `""`=전체(아무 적/아무 미니게임), 특정 값=해당 대상만 | 적 필터·미니게임 id를 하나의 필드로 통일. Report 매칭 규칙 단일화 |
| 9 | Fragment(개념조각) 보상 제외 | 소비처가 없어 쌓이기만 함 — `13 출석` 결정과 동일 |

### 3-1. 리셋 유틸 확장 — `DailyResetHelper` 주간 메서드 추가

```csharp
// Scripts/Meta/DailyResetHelper.cs 에 추가
// (기존 Today()/ThisMonth()/DayOfMonth()/IsNewDay()는 13에서 이미 존재)

/// <summary>이번 주 월요일 날짜 "yyyy-MM-dd" (주간 리셋 키).</summary>
public static string ThisWeekKey()
{
    var now = DateTime.Now.Date;
    int daysSinceMonday = ((int)now.DayOfWeek + 6) % 7; // 월=0 … 일=6
    return now.AddDays(-daysSinceMonday).ToString("yyyy-MM-dd");
}

/// <summary>마지막 주 키가 이번 주가 아니면 true(새 주).</summary>
public static bool IsNewWeek(string lastWeekKey) => lastWeekKey != ThisWeekKey();
```

    };

    public static readonly MissionReward DailyBonus  = Cur(CurrencyKind.Paper, 20);
    public static readonly MissionReward[] WeeklyBonus =
    {
        Cur(CurrencyKind.Paper, 80),
        Crystal(CrystalKind.PrimeForce, 10),  // 결정 종류는 튜닝 대상(저등급/범용 권장)
    };

    public static MissionDef[] For(MissionScope s) => s == MissionScope.Daily ? Daily : Weekly;

    static MissionDef Def(string id, MissionScope s, MissionObjectiveType o, int t, string ctx, MissionReward r)
        => new MissionDef { id = id, scope = s, objective = o, target = t, contextId = ctx, reward = r };
    static MissionReward Cur(CurrencyKind k, int a)
        => new MissionReward { type = MissionRewardType.Currency, kindIndex = (int)k, amount = a };
    static MissionReward Crystal(CrystalKind k, int a)
        => new MissionReward { type = MissionRewardType.Crystal, kindIndex = (int)k, amount = a };

> **미래 문서 연동점**
> - **적 리스트 문서**: `대륙·국가·세부위치·이름·권장레벨·스킬` 표. 적 처치 목표의
>   `contextId`를 "플레이어 레벨대에 맞는 적 그룹" 필터로 채우는 근거가 된다.
>   확정 전까지 `contextId=""`(전체 처치)로 동작.
> - **미니게임 문서**: 미니게임별 id·룰·점수 체계. `MinigamePlay`/`MinigameScore`
>   목표의 `contextId`(미니게임 id)와 점수 기준(target)이 이 문서를 따른다.
>   미니게임 시스템이 `MissionService.Report(...)`를 호출하는 순간 자동 연동.

### 3-4. 상태 — `MissionState` (+ `MissionData` DTO)

```csharp
// Scripts/Meta/MissionState.cs
using System;
using System.Collections.Generic;

[Serializable]
public class MissionState
{
    public string lastDailyReset = "";   // "yyyy-MM-dd"
    public string lastWeeklyKey  = "";   // 이번 주 월요일 "yyyy-MM-dd"

    // 런타임 진행/수령 상태 (DTO로는 병렬 배열 직렬화)
    Dictionary<string,int> _progress = new();   // missionId -> 현재 수치
    HashSet<string> _claimed = new();           // 수령 완료 missionId
    bool _dailyBonusClaimed;
    bool _weeklyBonusClaimed;

    /// <summary>패널 오픈/Report 시마다 호출. 날짜·주가 바뀌면 해당 구분 초기화.</summary>
    public void SyncCycle()
    {
        if (DailyResetHelper.IsNewDay(lastDailyReset))
        {
            lastDailyReset = DailyResetHelper.Today();
            ClearScope(MissionScope.Daily);
            _dailyBonusClaimed = false;
        }
        if (DailyResetHelper.IsNewWeek(lastWeeklyKey))
        {
            lastWeeklyKey = DailyResetHelper.ThisWeekKey();
            ClearScope(MissionScope.Weekly);
            _weeklyBonusClaimed = false;
        }
    }

    void ClearScope(MissionScope s)
    {
        foreach (var m in MissionCatalog.For(s))
        {
            _progress.Remove(m.id);
            _claimed.Remove(m.id);
        }
    }

    public int  Progress(string id)   => _progress.TryGetValue(id, out var v) ? v : 0;
    public bool IsClaimed(string id)  => _claimed.Contains(id);
    public bool BonusClaimed(MissionScope s) => s == MissionScope.Daily ? _dailyBonusClaimed : _weeklyBonusClaimed;

    public void AddProgress(string id, int amount, bool useMax)
    {
        int cur = Progress(id);
        _progress[id] = useMax ? Math.Max(cur, amount) : cur + amount;
    }
    public bool IsComplete(MissionDef d) => Progress(d.id) >= d.target;
    public void MarkClaimed(string id) => _claimed.Add(id);
    public void MarkBonusClaimed(MissionScope s)
    { if (s == MissionScope.Daily) _dailyBonusClaimed = true; else _weeklyBonusClaimed = true; }

    // ---- 직렬화 (JsonUtility는 Dict/HashSet 미지원 → 병렬 배열) ----
    public MissionData Export()
    {
        var ids = new List<string>(_progress.Keys);
        var amts = new List<int>();
        foreach (var k in ids) amts.Add(_progress[k]);
        return new MissionData {
            lastDailyReset = lastDailyReset,
            lastWeeklyKey  = lastWeeklyKey,
            progressIds    = ids.ToArray(),
            progressAmts   = amts.ToArray(),
            claimedIds     = new List<string>(_claimed).ToArray(),
            dailyBonusClaimed  = _dailyBonusClaimed,
            weeklyBonusClaimed = _weeklyBonusClaimed,
        };
    }

    public void LoadState(MissionData d)
    {
        if (d == null) return;
        lastDailyReset = d.lastDailyReset ?? "";
        lastWeeklyKey  = d.lastWeeklyKey ?? "";
        _progress.Clear(); _claimed.Clear();
        if (d.progressIds != null && d.progressAmts != null)
            for (int i = 0; i < d.progressIds.Length && i < d.progressAmts.Length; i++)
                _progress[d.progressIds[i]] = d.progressAmts[i];
        if (d.claimedIds != null)
            foreach (var id in d.claimedIds) _claimed.Add(id);
        _dailyBonusClaimed  = d.dailyBonusClaimed;
        _weeklyBonusClaimed = d.weeklyBonusClaimed;
    }
}

[Serializable]
public class MissionData
{
    public string   lastDailyReset;
    public string   lastWeeklyKey;
    public string[] progressIds;
    public int[]    progressAmts;
    public string[] claimedIds;
    public bool     dailyBonusClaimed;
    public bool     weeklyBonusClaimed;
}
```

### 3-5. 서비스 — `MissionService`

```csharp
// Scripts/Meta/MissionService.cs
public static class MissionService
{
    /// <summary>진행 이벤트 보고. 전투/미니게임이 호출.
    /// contextId="" 인 목표는 아무 대상이나 매칭, 값이 있으면 동일 대상만 매칭.</summary>
    public static void Report(MissionObjectiveType type, int amount, string contextId = "")
    {
        var s = MetaState.Missions;
        s.SyncCycle();
        bool changed = false;
        foreach (var scope in new[] { MissionScope.Daily, MissionScope.Weekly })
            foreach (var d in MissionCatalog.For(scope))
            {
                if (d.objective != type) continue;
                if (!string.IsNullOrEmpty(d.contextId) && d.contextId != contextId) continue;
                if (s.IsClaimed(d.id) || s.IsComplete(d)) continue;
                bool useMax = (type == MissionObjectiveType.MinigameScore);
                s.AddProgress(d.id, amount, useMax);
                changed = true;
            }
        if (changed) MetaSaveService.Save();
    }

    /// <summary>완료된 미수령 임무 보상 수령.</summary>
    public static bool Claim(string missionId)
    {
        var s = MetaState.Missions;
        s.SyncCycle();
        if (!TryFind(missionId, out var d)) return false;
        if (s.IsClaimed(d.id) || !s.IsComplete(d)) return false;
        Grant(d.reward);
        s.MarkClaimed(d.id);
        MetaSaveService.Save();
        return true;
    }

    /// <summary>해당 구분 임무 전부 수령 시 완전클리어 보너스 1회.</summary>
    public static bool ClaimBonus(MissionScope scope)
    {
        var s = MetaState.Missions;
        s.SyncCycle();
        if (s.BonusClaimed(scope)) return false;
        foreach (var d in MissionCatalog.For(scope))
            if (!s.IsClaimed(d.id)) return false;   // 전부 수령해야 보너스 개방
        if (scope == MissionScope.Daily) Grant(MissionCatalog.DailyBonus);
        else foreach (var r in MissionCatalog.WeeklyBonus) Grant(r);
        s.MarkBonusClaimed(scope);
        MetaSaveService.Save();
        return true;
    }

    static bool TryFind(string id, out MissionDef def)
    {
        foreach (var scope in new[] { MissionScope.Daily, MissionScope.Weekly })
            foreach (var d in MissionCatalog.For(scope))
                if (d.id == id) { def = d; return true; }
        def = default; return false;
    }

    static void Grant(MissionReward r)
    {
        switch (r.type)
        {
            case MissionRewardType.Currency: MetaState.Wallet.Add((CurrencyKind)r.kindIndex, r.amount); break;
            case MissionRewardType.Crystal:  MetaState.Crystals.Add((CrystalKind)r.kindIndex, r.amount); break;
        }
    }
}
```

### 3-6. UI — `MissionPanel` (`AccountPanel` 패턴 복제)

- 진입: 계정·출석 버튼 옆 상시 버튼 → `Open()` (UIManager 중재). 자동 팝업은 하지 않음

- `Open()` 시 `MetaState.Missions.SyncCycle()` 호출 후 그려서 리셋을 반영(캐시 안 함).

## 6. 엣지 케이스 / 주의점

- **월요일 자정 = 일일+주간 동시 리셋**: `SyncCycle()`이 두 조건을 각각 검사하므로
  월요일 첫 접속 시 일일·주간이 함께 초기화된다.
- **Report 시점에도 SyncCycle**: 패널을 안 열어도 전투/미니게임 Report가 들어오므로
  Report 진입 시 `SyncCycle()`을 먼저 호출해 스테일 데이 진행 누적을 막는다(캐시 금지).
- **점수 목표는 max 갱신**: `MinigameScore`는 합산이 아니라 최고 기록(`AddProgress useMax`).
  낮은 점수 Report가 이미 도달한 진행도를 깎지 않는다.
- **contextId 매칭 규칙**: 목표 `contextId=""`는 아무 대상이나 매칭, 값이 있으면 동일
  대상만. 적 리스트/미니게임 문서 확정 시 이 필드만 채우면 대상 지정이 활성화된다.
- **완전클리어 보너스 개방 조건**: 그 구분 임무를 **전부 `Claim`** 해야 보너스가 열린다
  (완료만으로는 부족). 카탈로그에 임무를 추가하면 조건이 그 임무까지 포함해 재평가됨.
- **중복 수령/이중 카운트 차단**: `Claim`은 `IsClaimed` 가드, `Report`는 이미 완료·수령된
  임무를 건너뛴다.
- **저장 하위호환**: `KEY_MISSIONS` 없는 구세이브 → 빈 DTO → 첫 `SyncCycle()`이 당일/당주로
  초기화. 별도 마이그레이션 불필요.
- **카탈로그 변경과 저장 데이터**: 임무 id 기준 저장이므로, 미래에 id를 바꾸면 기존
  진행도가 유실된다. id는 안정 키로 유지하고 목표치/보상만 조정할 것.
- **기기 시간 조작**: 12·13과 동일하게 v1은 클라이언트 `DateTime.Now` 권위. 서버 검증은 후속.

## 7. 검증 방법

### EditMode 테스트 (`MissionTests.cs`)
- `lastDailyReset`을 어제로 강제 → `SyncCycle()` → 일일 임무 진행/수령 초기화, 주간은 불변 확인.
- `lastWeeklyKey`를 지난주로 강제 → `SyncCycle()` → 주간만 초기화 확인.
- `Report(EnemyKill,5)` ×N → 해당 일일·주간 킬 임무 진행도 동시 증가, 목표 초과 시 `IsComplete`.
- `Report(MinigameScore,100)` 후 `Report(MinigameScore,40)` → 진행도 100 유지(max) 확인.
- `Claim` 완료 임무 성공 → 보상 지급 + 재 `Claim` 실패(중복 차단).
- 미완료 임무 `Claim` 실패.
- 일일 3종 전부 `Claim` 후 `ClaimBonus(Daily)` 성공, 재호출 실패. 하나라도 미수령이면 실패.
- `MissionRewardType.Currency`/`Crystal`이 각각 `Wallet`/`Crystals`에 정확히 지급되는지.
- `Export()` → `LoadState()` 왕복 후 진행도·수령·보너스 상태 일치 확인.

### 인게임 (PowerShell 스크린샷)
1. `MSRPG > Setup Mesoria Scene` → `MSRPG > Setup Meta UI` 재빌드.
2. 상시 버튼으로 `MissionPanel` 열기 → 일일/주간 탭·진행바 확인.
3. 전투에서 적 처치 → 임무 열면 킬 임무 진행도 증가 확인.
4. 목표 달성 후 [수령] → 재화 HUD 증가 + 버튼 비활성 확인.
5. 일일 전부 수령 → [보너스 수령] 활성 → 논문 20 지급 확인.
6. 기기 날짜 하루 앞으로 → 재진입 → 일일 초기화(주간 유지) 확인.
