# 미니게임 시스템 (프레임워크 + 채워넣는 틀)

> `15 일일·주간 임무`가 미니게임에 대해 `Report(MinigamePlay,1,gameId)` /
> `Report(MinigameScore,score,gameId)` 훅과 `contextId=미니게임 id`, 점수 기준을 이 문서에
> 위임했다(15 문서 결정 #4). **개별 미니게임 내용·개수는 사용자가 직접 채운다** — 이 문서는
> 게임 하나하나가 아니라, 게임을 계속 끼워 넣을 수 있는 **틀(프레임워크)**을 정의한다.

---

## 세계관 맥락

배움의 전당은 학생에게 소일거리 겸 실습용 **작은 놀이(미니게임)**를 제공한다. 무겁게 개념을
파고드는 R&E(문제 풀이 → 스킬 성장)와 달리, 미니게임은 짧고 재도전형이다. 이 문서는 놀이
하나하나가 아니라, 놀이를 계속 들여놓을 수 있는 **오락관(프레임워크)**을 짓는다.

---

## 1. 목표 / 완료 정의

1. **끼워 넣는 틀 완성**: 새 미니게임 = 카탈로그 항목 1개(`MinigameDef`) + `IMinigame` 구현
   프리팹 1개만 추가하면 목록·플레이·보상·저장·임무연동이 자동으로 동작.
2. **공용 오락관(`MinigameHost`)**: 인트로(이름·설명·조작) → 카운트다운 → 게임 실행 →
   타이머/점수 HUD → 결과 화면 → 제출까지 모든 게임 공통 흐름을 한 곳에서 처리.
3. **자체 보상**: 게임별 하루 1번, 그날 최고점의 보상 구간 지급(일일 리셋).
4. **15 임무 연동**: 제출 시 `Report(MinigamePlay,1,id)` + `Report(MinigameScore,score,id)` 자동 호출.
5. **진입**: 상시 버튼 → `MinigameListPanel`에서 목록 나열·선택 실행.
6. **저장·복원**: 게임별 최고점·오늘 판수·오늘 보상수령·마지막 리셋일이 PlayFab에 저장.
7. **데모 게임 1개**(`QuickCalc`)로 전체 흐름을 인게임에서 눈으로 검증.

### 확정 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| 1 | 틀 = **데이터 서술(`MinigameDef`) + 코드 계약(`IMinigame`)** 2층 | 데이터만으론 다양한 메커닉(혼합) 표현 불가. 계약을 두면 새 게임이 규칙만 작성 |
| 2 | 공통 흐름은 **`MinigameHost`가 전담**, 개별 게임은 순수 규칙만 | 타이머·점수·결과·보상·임무보고 중복 제거. 게임 추가 비용 최소화 |
| 3 | 점수는 **항상 "높을수록 좋음"** | 15 `MinigameScore`가 max 기준. 시간단축형은 `남은시간×N` 등으로 점수화 |
| 4 | 자체 보상 = **게임별 하루 1번**(그날 최고 구간) | 인플레 방지. 12·13·15와 같은 일일 리셋 기조 |
| 5 | 일일 리셋은 **`DailyResetHelper`** 재사용(없으면 이 문서에서 신설) | 13이 확립 예정인 canonical 리셋 유틸. 파일 분산 방지 |
| 6 | 보상 재화는 **골드/논문/집중력(Wallet)·결정(Crystals)** | 기존 재화 재사용. Fragment 제외(소비처 없음, 13·15와 동일) |
| 7 | 게임 알맹이는 **프리팹 참조(`prefabKey`)**로 느슨히 연결 | 카탈로그가 구현체를 몰라도 됨. 게임은 독립 프리팹으로 추가 |

## 3. 아키텍처

### 3-1. 데이터 서술 층 — `MinigameDef` (채워넣는 "게임 카드")

```csharp
// Scripts/Meta/MinigameTypes.cs
public enum MinigameCategory { Educational, Arcade }
public enum MinigameRewardKind { Currency, Crystal }

[System.Serializable]
public struct MinigameRewardTier   // 점수 임계 → 보상 (minScore 내림차순 정렬)
{
    public int minScore;            // 이 점수 이상이면
    public MinigameRewardKind kind; // Currency / Crystal
    public int kindIndex;           // CurrencyKind 또는 CrystalKind 정수값
    public int amount;
}

[System.Serializable]
public struct MinigameDef
{
    public string id;               // ★ 식별 코드(contextId). 안정 키—절대 바꾸지 말 것
    public string displayName;      // ★ 표시 이름
    public string summary;          // ★ 한 줄 설명(목록)
    public string howToPlay;        // 조작 안내(인트로)
    public MinigameCategory category;
    public string subjectTag;       // 과목 태그("수학" 등, 선택)
    public float  timeLimitSec;     // 0 = 게임이 스스로 종료
    public string scoreUnit;        // 점수 단위 표시("맞힌 개수")
    public MinigameRewardTier[] rewards; // 자체 보상표(하루 1번, 최고 구간 지급)
    public string prefabKey;        // ★ 게임 알맹이 프리팹 참조(Resources 경로/등록키)
}
```

**"게임 카드" 빈칸 요약** (사용자가 새 미니게임을 추가할 때 채우는 것):

| 빈칸 | 뜻 | 필수 |
|------|-----|:---:|
| 식별 코드(`id`) | 시스템이 구분하는 영문 이름표. 한 번 정하면 바꾸지 않음(임무·기록이 여기 묶임) | ★ |
| 이름(`displayName`) | 목록·화면에 보이는 한글 이름 | ★ |
| 한 줄 설명(`summary`) | 목록에서 보이는 소개 | ★ |
| 조작 안내(`howToPlay`) | 시작 전 "어떻게 하는지" 안내 | |
| 분류(`category`/`subjectTag`) | 교육형/아케이드 + 과목 태그 | |
| 제한시간(`timeLimitSec`) | 몇 초인지. 0이면 게임이 스스로 종료 | |
| 점수 단위(`scoreUnit`) | 점수가 무엇을 세는지(표시용). **점수는 항상 "높을수록 좋음"** | ★ |
| 보상표(`rewards`) | 점수 구간별 보상. 하루 한도(게임별 1번) 안에서 그날 최고 구간 지급 | |
| 게임 알맹이 연결(`prefabKey`) | 실제 게임 프리팹 참조 | ★ |

### 3-2. 카탈로그 — `MinigameCatalog` (사용자가 게임을 추가하는 목록)

```csharp
// Scripts/Meta/MinigameCatalog.cs
public static class MinigameCatalog
{
    public static readonly MinigameDef[] All =
    {
        // ── 데모(틀 검증용). 실제 게임은 사용자가 이 배열에 항목 추가 ──
        new MinigameDef {
            id = "quick_calc", displayName = "빛의 속도 계산",
            summary = "제한시간 안에 계산 문제를 최대한 많이!",
            howToPlay = "화면의 답을 눌러 맞히세요. 틀리면 감점 없음.",
            category = MinigameCategory.Educational, subjectTag = "수학",
            timeLimitSec = 60f, scoreUnit = "맞힌 개수",
            prefabKey = "Minigames/QuickCalc",
            rewards = new [] {
                Tier(20, MinigameRewardKind.Currency, (int)CurrencyKind.Gold, 500),
                Tier(10, MinigameRewardKind.Currency, (int)CurrencyKind.Gold, 200),
            },
        },
    };

    public static bool TryGet(string id, out MinigameDef def) {
        foreach (var d in All) if (d.id == id) { def = d; return true; }
        def = default; return false;
    }
    static MinigameRewardTier Tier(int min, MinigameRewardKind k, int idx, int amt)
        => new MinigameRewardTier { minScore = min, kind = k, kindIndex = idx, amount = amt };
}
```

### 3-3. 코드 계약 층 — `IMinigame` + `MinigameContext`

```csharp
// Scripts/Minigame/IMinigame.cs
public interface IMinigame
{
    void Begin(MinigameContext ctx);  // Host가 카운트다운 후 호출. 여기서 게임 시작
    void ForceEnd();                  // 타이머 만료 등 강제 종료. 정리 후 ctx.Finish 호출
}

public class MinigameContext
{
    public MinigameDef Def;
    System.Action<int> _onScore, _onFinish;
    public MinigameContext(MinigameDef d, System.Action<int> onScore, System.Action<int> onFinish)
        { Def = d; _onScore = onScore; _onFinish = onFinish; }
    public void SetScore(int current) => _onScore?.Invoke(current); // 실시간 점수 HUD(선택)
    public void Finish(int finalScore) => _onFinish?.Invoke(finalScore); // 종료 확정
}
```

개별 게임 = `MonoBehaviour` + `IMinigame` 구현 프리팹. 규칙만 작성하고, 끝나면 `ctx.Finish(score)`.

### 3-4. 공용 오락관 — `MinigameHost` (MonoBehaviour)

```
Launch(MinigameDef def):
  1) UIManager.TryOpen()
  2) 인트로 화면: displayName / summary / howToPlay / scoreUnit 표시, [시작] 버튼
  3) 카운트다운 3·2·1
  4) prefabKey로 게임 프리팹 인스턴스화 → IMinigame.Begin(ctx)
  5) def.timeLimitSec>0 이면 타이머 표시, 0 도달 시 IMinigame.ForceEnd()
  6) ctx.SetScore(n) → 점수 HUD 갱신
  7) ctx.Finish(score) → 게임 프리팹 파괴 → 결과 화면(점수·획득 보상)
                       → MinigameService.Submit(def.id, score) → UIManager.Close()
  [나가기] 언제든 중도 종료 → ForceEnd 없이 폐기(제출·기록 없음)
```

### 3-5. 서비스 — `MinigameService` (static)

```csharp
// Scripts/Meta/MinigameService.cs
public static class MinigameService
{
    public static void Submit(string id, int score)
    {
        var s = MetaState.Minigames;
        s.SyncDay();
        if (!MinigameCatalog.TryGet(id, out var def)) return;
        s.RecordPlay(id, score);                 // best = max(best,score), 오늘 판수 +1

        // 자체 보상: 하루 1번, 그날 최고 구간
        if (!s.RewardedToday(id))
        {
            if (TryBestTier(def, score, out var tier)) { Grant(tier); s.MarkRewarded(id); }
        }

        // 15 임무 연동 (15 미구현 시 이 2줄 주석 처리)
        MissionService.Report(MissionObjectiveType.MinigamePlay,  1,     id);
        MissionService.Report(MissionObjectiveType.MinigameScore, score, id);

        MetaSaveService.Save();
    }

    static bool TryBestTier(MinigameDef d, int score, out MinigameRewardTier best)
    {
        best = default; bool found = false;
        if (d.rewards != null)
            foreach (var t in d.rewards)                 // 도달한 구간 중 minScore 최대
                if (score >= t.minScore && (!found || t.minScore > best.minScore))
                    { best = t; found = true; }
        return found;
    }
    static void Grant(MinigameRewardTier t)
    {
        if (t.kind == MinigameRewardKind.Currency) MetaState.Wallet.Add((CurrencyKind)t.kindIndex, t.amount);
        else                                        MetaState.Crystals.Add((CrystalKind)t.kindIndex, t.amount);
    }
}
```

### 3-6. 상태 — `MinigameState` (+ `MinigameData` DTO)

```csharp
// Scripts/Meta/MinigameState.cs — best/오늘판수/오늘보상 + 일일 리셋
[System.Serializable]
public class MinigameState
{
    public string lastDailyReset = "";
    Dictionary<string,int> _best = new();        // id -> 최고점(영구)
    Dictionary<string,int> _playsToday = new();  // id -> 오늘 판수(리셋)
    HashSet<string> _rewardedToday = new();      // 오늘 자체보상 받은 id(리셋)

    public void SyncDay()
    {
        if (DailyResetHelper.IsNewDay(lastDailyReset))
        { lastDailyReset = DailyResetHelper.Today(); _playsToday.Clear(); _rewardedToday.Clear(); }
    }
    public int  Best(string id)        => _best.TryGetValue(id, out var v) ? v : 0;
    public int  PlaysToday(string id)  => _playsToday.TryGetValue(id, out var v) ? v : 0;
    public bool RewardedToday(string id)=> _rewardedToday.Contains(id);
    public void RecordPlay(string id, int score)
    {
        if (score > Best(id)) _best[id] = score;
        _playsToday[id] = PlaysToday(id) + 1;
    }
    public void MarkRewarded(string id) => _rewardedToday.Add(id);
    // Export()/LoadState(): JsonUtility가 Dict/HashSet 미지원 → 병렬 배열(15 MissionState 패턴 동일)
}
```

`MinigameData` DTO: `lastDailyReset`, `bestIds[]`/`bestScores[]`, `playIds[]`/`playCounts[]`,
`rewardedIds[]`. (best는 영구, play·rewarded는 리셋 대상이지만 저장은 셋 다 함—리셋은 SyncDay가 담당.)

### 3-7. UI — `MinigameListPanel` (`AccountPanel` 패턴 복제)

- 진입: 상시 버튼 → `Open()`(UIManager 중재). 자동 팝업 없음.
- 레이아웃: `MinigameCatalog.All` 나열. 행 = 이름 + 설명 + 최고점 + [오늘 보상 O/X] + [플레이].
- [플레이] → `MinigameHost.Launch(def)` (리스트 패널은 닫고 오락관으로 전환).
- `Open()` 시 `MetaState.Minigames.SyncDay()` 후 그려 일일 리셋 반영.

**데이터 흐름:**
```
상시 버튼 → MinigameListPanel(SyncDay·목록) → [플레이] → MinigameHost.Launch
  → 인트로 → 카운트다운 → IMinigame.Begin → (게임) → ctx.Finish(score)
  → 결과 화면 → MinigameService.Submit
      ├ best·오늘판수 기록
      ├ 자체 보상(하루1번, 최고구간) → Wallet/Crystals
      ├ MissionService.Report(MinigamePlay,1,id) / Report(MinigameScore,score,id)
      └ MetaSaveService.Save
```

## 6. 엣지 케이스 / 주의점

- **Submit 시 SyncDay 먼저**: 자정 넘겨 플레이하면 오늘 판수·보상 리셋이 반영돼야 함(캐시 금지).
- **best는 max, 영구**: 낮은 점수 제출이 최고점을 깎지 않음. play/rewarded만 일일 리셋.
- **자체 보상 하루 1번**: `RewardedToday` 가드. 그날 최고 구간 1개만(중복·다구간 동시 지급 금지).
- **점수는 높을수록 좋음 강제**: 시간단축형은 `남은시간×N`로 점수화. 카탈로그 리뷰 시 확인.
- **id는 안정 키**: 바꾸면 best·기록 유실. 목표치/보상만 조정.
- **중도 나가기**: `ForceEnd` 없이 폐기 → 제출·기록·임무 카운트 없음(어뷰징 방지).
- **15 의존**: `MissionService.Report`는 15 구현 후 컴파일. 미구현 시 2줄 주석—틀 자체는 독립 동작.
- **저장 하위호환**: `KEY_MINIGAMES` 없는 구세이브 → 빈 DTO → 첫 SyncDay가 당일 초기화. 마이그레이션 불필요.
- **prefabKey 오타/누락**: Host가 프리팹 로드 실패 시 에러 토스트 후 리스트로 복귀(크래시 금지).

## 7. 검증 방법

### EditMode (`MinigameTests.cs`)
- `Submit("quick_calc", 25)` → best=25, 판수=1, 골드+500(20점 구간), rewardedToday=true.
- 같은 날 재 `Submit(..,30)` → best=30, 판수=2, **보상 추가 없음**(하루1번).
- `Submit(..,5)`(어떤 구간도 미달) → 보상 없음, best 불변(더 낮으면).
- `lastDailyReset`을 어제로 강제 → `SyncDay` → 판수·rewarded 리셋, best 유지.
- `Export()`→`LoadState()` 왕복 후 best/판수/보상수령 일치.
- (15 존재 시) Submit 후 해당 미니게임 임무 진행도(play+1, score=max) 증가 확인.

### 인게임 (PowerShell 스크린샷)
1. `MSRPG > Setup Mesoria Scene` → `MSRPG > Setup Meta UI` 재빌드.
2. 상시 버튼 → 목록에 데모 게임 표시 확인.
3. [플레이] → 인트로·카운트다운·타이머·점수 HUD 동작 확인.
4. 종료 → 결과 화면 점수·보상 표시, 재화 HUD 증가 확인.
5. 재플레이 → 보상 미지급(하루1번), best 갱신 확인.
6. 기기 날짜 +1일 → 재진입 → 판수·보상 리셋(최고점 유지) 확인.

### 저장·복원
- 플레이 후 PlayMode 종료 → 재시작 → best·리셋일 유지 확인.
