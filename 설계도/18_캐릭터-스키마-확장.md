# 18. 캐릭터 스키마 확장 + 교육 시스템

## 세계관 맥락

- `캐릭터 정리.txt`에 물리 7종(시간·길이공간·전하량전기장·자기장·빛·쿼크·질량관성)이 성별·컨셉·외형·무기·스킬까지 완성돼 있으나, 게임 안 `CharacterDef.asset`은 스탯·이름·스킬 GUID만 있고 concept/appearance/loreKo가 비어 있다 — **텍스트 설정과 게임 데이터가 단절된 상태**.
- 상단 메모("적 캐릭터 속성에 운동량·질량 등 → 값에 따라 받는 피해 달라지도록", "일반공격 커스터마이징", "히든 스킬", "캐릭터 성격 설정 필요", "시너지 스킬")가 지금 `CharacterDef` 스키마엔 반영 자리가 없다.
- 이 설계도는 **캐릭터 콘텐츠 저작 파이프라인(CSV 3+1장) + 스키마 확장 + 그 데이터를 소비하는 핵심 전투/교육 시스템**을 다룬다. 시너지 연계 메커니즘 자체(표식 소모·연계기)는 이미 [03_시너지-연계-시스템.md](03_시너지-연계-시스템.md)가 소유하므로 **여기서는 재정의하지 않고 그 필드(`markId`)에 맞춰 저작만 지원**한다.

---

## 1. 목표 / 완료 정의

1. `Resources/Data/character_catalog.csv` + `character_skills.csv` + `tag_rules.csv` + `character_codex.csv` 4장을 편집하고 임포터를 실행하면 `CharacterDef`/`SkillDef`/`ProblemDef` 에셋이 생성·갱신된다 (Unity 없이 CSV만 텍스트 에디터로 편집 가능 — 지금 Unity 사용 곤란 상황과 무관하게 콘텐츠 제작 가능).
2. 캐릭터가 실제 물리량 수치(질량·속도·온도·전하)를 갖고, 스킬의 강점태그가 그 수치를 읽어 **연속적인 데미지 배율**을 계산한다 (`Enemy.ReceiveHit` 확장).
3. 막타로 적을 정확히 처치할수록(오버킬 적을수록) 높은 경험치 배율을 받는 **정밀 처치 등급제**가 동작한다.
4. 도감이 **기본 해설은 항상 노출**, **개념 문제 정답 시 심화 해설(실제 수식 포함)**을 여는 2단 구조로 표시되고, 실제 과학 원리·출처가 함께 표시된다.
5. 호감도 대화에 캐릭터별 **개념 성향 2지선다** 질문이 추가될 수 있는 데이터 자리가 생긴다 ([10_호감도.md](10_호감도.md) 연동).
6. 이후 "실험실" 건물(대륙별, 이번 범위 밖)이 그대로 가져다 쓸 수 있는 **속성→파생량 계산 순수 함수**가 정의된다.

**완료 정의**: 이 설계도 하나만 보고 다음 세션이 CSV 스키마·임포터·신규 C# 타입·전투 파이프라인 훅을 바로 구현 시작할 수 있는 상태. **이번 세션 산출물은 이 문서뿐 — 코드 변경 없음.**

## 3. 아키텍처

### 3-1. 저작 파이프라인 개요

```
character_catalog.csv ─┐
character_skills.csv  ─┼─→ CharacterCsvImporter (에디터 메뉴) ─→ CharacterDef.asset / SkillDef.asset
tag_rules.csv          ─┤                                       (+ CharacterDatabase 재빌드)
character_codex.csv    ─┘                                       (+ ProblemDef.asset — 개념문제)
```
`tag_rules.csv`는 캐릭터/스킬과 무관한 **전역 사전 1장** — TagRuleTable(static)로 로드.

### 3-4. CSV ③ `Resources/Data/tag_rules.csv` — 강점태그 사전 (전역 1장, 2층 구조)

| 열 | 노출 여부 | 설명 |
|---|---|---|
| `tagId` | (키) | 예: `고온` |
| `displayKo` | **플레이어 노출** | 예: "열에 취약" |
| `iconId` | **플레이어 노출** | 아이콘 리소스 id |
| `targetAttr` | 계산 전용(숨김) | `mass`/`velocity`/`temp`/`charge` 중 하나 — 대상의 어느 속성을 읽을지 |
| `direction` | 계산 전용(숨김) | `high`(속성값 클수록 유리) / `low`(작을수록 유리) |
| `baseMult` | 계산 전용(숨김) | 기본 배율 (보통 1.0) |
| `coeffPerUnit` | 계산 전용(숨김) | 속성값 1단위당 배율 증가량 |
| `refValue` | 계산 전용(숨김) | 기준값 (이 값과의 차이만큼 배율 변화) |
| `capMult` | 계산 전용(숨김) | 배율 상한 |

**최종 배율 공식** (`TagRule.Evaluate(targetValue)`):
```
delta = (direction == High) ? (targetValue - refValue) : (refValue - targetValue)
mult  = clamp(baseMult + coeffPerUnit * delta, baseMult, capMult)
```
"자세히 보기" UI는 이 계수들로 실제 수식 문자열을 조립해 표시한다:
```
"배율 = {baseMult} + {coeffPerUnit} × (대상 {targetAttr에 대응하는 한글명} − {refValue}), 최대 {capMult}배"
```
→ 자유 수식 문자열을 런타임 파싱하지 않고도 "진짜 계산에 쓰이는 수식"을 그대로 보여준다(파싱 리스크 없이 동일 효과).

v1 물리 태그 초안:

| tagId | displayKo | targetAttr | direction | baseMult | coeffPerUnit | refValue | capMult |
|---|---|---|---|---|---|---|---|
| 고온 | 열에 취약 | temp | high | 1.0 | 0.001 | 300 | 2.0 |
| 저온 | 냉기에 취약 | temp | low | 1.0 | 0.002 | 300 | 1.8 |
| 고속 | 빠른 적 특효 | velocity | high | 1.0 | 0.01 | 50 | 1.8 |
| 저속 | 둔한 적 특효 | velocity | low | 1.0 | 0.01 | 50 | 1.8 |
| 고질량 | 무거운 적 특효 | mass | high | 1.0 | 0.005 | 100 | 1.8 |
| 저질량 | 가벼운 적 특효 | mass | low | 1.0 | 0.005 | 100 | 1.8 |
| 양전하 | 양전하 반응 | charge | high | 1.0 | 0.01 | 0 | 1.8 |
| 음전하 | 음전하 반응 | charge | low | 1.0 | 0.01 | 0 | 1.8 |

### 3-6. 신규 C# 타입

```csharp
// Scripts/Meta/AttributeProfile.cs
[System.Serializable]
public struct AttributeProfile
{
    public int mass, velocity, temp, charge;   // v1 물리 4종. 값 0 = "이 속성 없음"
}

// Scripts/Meta/SkillType.cs
public enum SkillType { Active, Passive, FormChange, Mark }

// Scripts/Meta/TagRule.cs
[System.Serializable]
public class TagRule
{
    public string tagId, displayKo, iconId;
    public string targetAttr;     // "mass"|"velocity"|"temp"|"charge"
    public bool   directionHigh;  // true=high, false=low
    public float  baseMult, coeffPerUnit, refValue, capMult;

    public float Evaluate(AttributeProfile target)
    {
        int v = targetAttr switch { "mass" => target.mass, "velocity" => target.velocity,
                                     "temp" => target.temp, "charge" => target.charge, _ => 0 };
        float delta = directionHigh ? (v - refValue) : (refValue - v);
        return Mathf.Clamp(baseMult + coeffPerUnit * delta, baseMult, capMult);
    }

    public string FormulaKo(string attrLabelKo) =>
        $"배율 = {baseMult} + {coeffPerUnit} × (대상 {attrLabelKo} − {refValue}), 최대 {capMult}배";
}

// Scripts/Meta/TagRuleTable.cs — tag_rules.csv 로드 결과 (static, CharacterCsvImporter가 빌드)
[CreateAssetMenu(menuName = "MSRPG/Tag Rule Table")]
public class TagRuleTable : ScriptableObject
{
    public TagRule[] rules;
    public TagRule Find(string tagId) => System.Array.Find(rules, r => r.tagId == tagId);
}

// Scripts/Meta/SkillUnlockCondition.cs — unlockCond 문자열 파서
public enum SkillUnlockConditionType { Always, DamageTakenPercent, PromotionRankAtLeast, StoryFlag }
public struct SkillUnlockCondition
{
    public SkillUnlockConditionType type;
    public float numericParam;   // DamageTakenPercent=0~1, PromotionRankAtLeast=랭크
    public string stringParam;   // StoryFlag id

    public static SkillUnlockCondition Parse(string raw)
    {
        if (string.IsNullOrEmpty(raw)) return new SkillUnlockCondition { type = SkillUnlockConditionType.Always };
        var parts = raw.Split(':');
        return parts[0] switch
        {
            "DamageTakenPercent"    => new SkillUnlockCondition { type = SkillUnlockConditionType.DamageTakenPercent, numericParam = float.Parse(parts[1]) },
            "PromotionRankAtLeast"  => new SkillUnlockCondition { type = SkillUnlockConditionType.PromotionRankAtLeast, numericParam = float.Parse(parts[1]) },
            "StoryFlag"             => new SkillUnlockCondition { type = SkillUnlockConditionType.StoryFlag, stringParam = parts[1] },
            _                       => new SkillUnlockCondition { type = SkillUnlockConditionType.Always },
        };
    }
}

// Scripts/Combat/DerivedQuantity.cs — 실험실이 소비할 순수 함수 (이번 범위: 함수만)
public static class DerivedQuantity
{
    public static float Momentum(AttributeProfile a)        => a.mass * a.velocity;              // p = mv
    public static float KineticEnergy(AttributeProfile a)   => 0.5f * a.mass * a.velocity * a.velocity; // Ek = ½mv²
}
```

CSV 예시 `unlockCond` 값: `DamageTakenPercent:0.5` (질량 각성 — 최대체력 50% 이상 누적 피해), `StoryFlag:quantum_continent_unlocked` (쿼크 늦은 등장).

```csharp
/// <summary>강점태그를 반영한 피격. SkillExecutor가 강점태그 보유 스킬에서 호출.</summary>
public void ReceiveHit(Continent attackerElement, int atk, string[] strengthTags)
{
    float mult = 1f;
    if (strengthTags != null)
        foreach (var tagId in strengthTags)
        {
            var rule = MetaState.TagRules?.Find(tagId);
            if (rule != null) mult *= rule.Evaluate(attributes);
        }
    int finalAtk = Mathf.RoundToInt(atk * mult);

    int hpBefore = _unit.Hp;
    ReceiveHit(attackerElement, finalAtk);   // 기존 경로 재사용(약점·방어 계산·이펙트 그대로)
    if (_unit.IsDead)
        PrecisionKillGrader.Grade(hpBefore, CombatMath.ComputeDamage(finalAtk, _unit.Def, attackerElement == _unit.Weakness));
}
```

### 3-10. 정밀 처치 등급 보상

```csharp
// Scripts/Combat/PrecisionKillGrader.cs
public static class PrecisionKillGrader
{
    // hpBefore = 이 타격 직전 적 HP, dmg = 이 타격의 최종 데미지(방어 적용 후)
    public static float Grade(int hpBefore, int dmg)
    {
        if (hpBefore <= 0) return 1f;
        float overkillRatio = (float)(dmg - hpBefore) / hpBefore;   // 0 이하 = 오버킬 없음(도달 못 함, 실제로는 죽었으므로 ≥0)
        return overkillRatio switch
        {
            <= 0.0f  => 2.0f,   // 완벽(±0)
            <= 0.10f => 1.5f,   // 우수
            <= 0.30f => 1.2f,   // 양호
            _        => 1.0f,   // 보통
        };
    }
}
```
반환된 배율은 `Die()`에서 `MetaState.StudyMaterials.Add(...)` 지급량에 곱해 적용(§4 수정 파일 참고). `overkillRatio <= 0f`는 이론상 `dmg == hpBefore`일 때만(그보다 작으면 안 죽었을 것이므로) — 등호 케이스가 "완벽".

## 6. 엣지 케이스 / 주의점

| 상황 | 처리 방식 |
|------|----------|
| 타 과목 캐릭터가 물리 강점태그 스킬에 맞음(속성값 전부 0) | `TagRule.Evaluate`가 0을 그대로 읽어 `refValue`와의 차이로 계산 — 극단적 배율 방지를 위해 `capMult` 상한이 항상 걸림. 과목간 변환표 도입 전까지는 "물리 속성 0"으로 간주(의도된 단순화, 버그 아님) |
| 강점태그 없는 기존 스킬(단순 타격) | `strengthTags` 빈 배열 → 기존 `ReceiveHit(Continent,int)` 그대로 호출, 배율 개입 없음(회귀 없음) |
| CSV 재-임포트 시 기존 `OwnedCharacter` 세이브 | `id` 불변이면 참조 유지. 신규 필드(`advancedCodexUnlocked` 등)는 기본값(false)으로 역직렬화 — 구 세이브도 정상 로드 |
| `unlockCond` 파싱 실패(오타 등) | `SkillUnlockCondition.Parse`가 알 수 없는 타입은 `Always`로 폴백 — "해금 안 됨"보다 "항상 해금"이 안전(스킬이 영구히 안 잡히는 것보다 낫다) |
| `FormChange` 캐릭터(빛)의 폼별 스킬 | `slot` 배열 구조는 그대로, 개별 스킬의 `formReq`로 현재 폼과 불일치 시 `CanCast`에서 `false` 반환(§3-7 연동은 구현 세션에서 `CombatCharacter.CanCast` 수정) |
| 정밀 처치 등급: 오버킬 계산 시점 | 방어력 적용 **후** 최종 데미지 기준(플레이어가 실제로 화면에서 보는 숫자와 일치) |
| 실험실 인터페이스 | 이번 세션은 시그니처 정의까지. 씬·건물·UI 배치는 별도 설계도 필요(대륙별로 반복될 패턴이라 템플릿화 여지 있음 — 착수 시 재검토) |
| 17번(적 도감) 미구현 상태에서 적 속성 저작 | 지금은 `Enemy.cs` 인스펙터 필드로 v1 대응. 17 구현 시 `enemy_catalog.csv`에 동일 4열 추가 + `EnemyDef`가 값을 넘겨주도록 갱신 필요(교차 문서 노트 §4 참고) |
