# 16. 계절·시간 시스템

> **전부 실시간(`DateTime.Now`)의 순수 함수**로 계절과 낮/밤을 결정한다. 출석(13)의
> `DailyResetHelper`와 같은 "클라이언트 권위 로컬 시각" 정책을 따르되, **저장 상태가 전혀
> 없다** — 시계를 누적/저장하지 않고 현재 시각에서 매번 계산한다.

---

## 세계관 맥락

- 세계관 문서상 대륙마다 고유 기후가 있다: 메조리아 = "온화한 해양성 지중해 기후,
  사계절이 뚜렷하되 극단적이지 않음", 아틀란티스 = "추상 기후(증명 조각이 내림)",
  물리 = "고전 지역 예측가능 사계절 / 양자 지역 불안정", 화학 = "반응성 다색 기후" 등.
- **대륙 경계**에서는 두 대륙의 기후가 중간값으로 섞인다(세계관의 "교역 폭풍"처럼 타
  대륙 기후가 유입되는 정서와도 정합).
- 각 대륙의 구체적 기후 수치는 **구현 시점에 `세계관 아이디어-2.txt`를 참조**해 채운다.
  본 설계도는 그 구조(프로필·존·블렌딩)만 확립하고, 대륙별 상세는 "참조" 수준으로 남긴다.

## 1. 목표 / 완료 정의

1. **실시간 연동**: 게임을 켠 순간의 실제 날짜→계절, 실제 시각→낮/밤이 저절로 반영된다.
   (예: 7월 저녁에 켜면 "여름·저녁"으로 보인다.)
2. **연속 태양**: 하루 동안 태양(Directional Light) 각도·색·강도가 **끊김 없이 매끄럽게**
   변한다(일출·정오·노을·밤).
3. **이산 시간대 버킷**: 게임 규칙이 읽기 쉽게 `새벽/낮/저녁/밤` 4버킷을 노출한다.
4. **계절 팔레트**: 봄·여름·가을·겨울에 따라 하늘·빛·안개 색감이 달라지고, 계절 경계
   며칠은 다음 계절과 크로스페이드된다.
5. **대륙별 프로필 + 경계 블렌딩**: 대륙마다 기후 프로필을 갖고, 플레이어 위치가 두 대륙
   구역 사이에 있으면 두 프로필이 위치 비율로 블렌드되어 적용된다. **v1은 메조리아 프로필만
   구체 작성**, 나머지는 세계관 참조 스텁.
6. **게임플레이 훅**: `WorldClock`이 계절·시간대를 읽는 공개 API를 제공한다. v1 실제 연결은
   **데모 1개(밤/저녁에 메조리아 가로등·건물 조명 on, 낮에 off)**. 12/13/15·전투는 향후
   이 API를 읽어 붙이는 확장점으로 문서화.
7. **개발자 오버라이드**: 실시간이라 여름엔 겨울을 못 보므로, 계절·시간대를 강제 지정해
   즉시 확인하는 디버그 스위치를 둔다(정식 기능 아님, 검증용).
8. **저장 불필요**: 순수 함수라 PlayFab 저장/복원 없음.

### 확정 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| 1 | 시간 소스 = **전부 실시간** `DateTime.Now`, 클라이언트 권위 | 13/12와 동일 정책. 누적 시계 저장 불필요 → 가장 단순, 상태 버그 없음 |
| 2 | 계절 = 현실 달 매핑(북반구): 봄 3–5, 여름 6–8, 가을 9–11, 겨울 12–2 | 직관적·몰입형. 국내 사용자 체감 계절과 일치 |
| 3 | 계절 경계 = **크로스페이드**(경계 ±N일, 기본 6일) | 달 바뀔 때 팔레트가 툭 튀지 않게. 경계 블렌딩과 같은 원리 |
| 4 | 낮/밤 = **연속 태양각 + 이산 4버킷** 병행 | 연출은 연속(노을 매끄럽게), 규칙은 이산(읽기 쉬움). 목적("시각+훅") 정합 |
| 5 | 시간대 버킷 기본 경계 = 새벽 05–08 / 낮 08–17 / 저녁 17–20 / 밤 20–05 | 튜닝 가능한 출발값. 계절별 일출/일몰 편차는 프로필 offset으로 후속 |
| 6 | 대륙별 **ClimateProfile** + 위치가중 **ClimateZone** 블렌딩 | "대륙마다 다르게, 경계는 중간" 요구를 직접 충족 |
| 7 | v1 구체 작성 = **메조리아만**. 타 대륙은 스텁/주석(세계관 참조) | 사용자 지시: 대륙별 상세는 구현 시 문제, 설계도엔 참고 수준 |
| 8 | 씬당 `EnvironmentController` 1개가 시계+존을 매 프레임 블렌드→적용 | scene_architecture: 수학만 별도 씬, 나머지는 메조리아 씬 안 → 씬 단위 적용이 맞음 |
| 9 | 날씨(강수·특수 파티클) = v1 제외, 프로필에 **빈 필드만** | YAGNI. 대기 연출부터. 교역폭풍·증명눈은 후속 |
| 10 | 게임플레이 훅 = **공개 API + 확장점 + 데모 1개** | 대상 시스템(12/13/15) 대부분 미구현. 13 출석의 이벤트 확장점과 동일 전략 |

## 3. 아키텍처

### 3-0. 데이터 흐름 한눈에

```
DateTime.Now ──▶ WorldClock (순수 static, 저장 없음)
                   ├─ CurrentSeason   (Spring/Summer/Autumn/Winter)  ← 현실 달
                   ├─ SeasonBlend     (인접 계절, weight)             ← 경계 ±6일 크로스페이드
                   ├─ DayFraction     (0~1, 자정=0)                  → 연속 태양각
                   └─ CurrentPhase    (Dawn/Day/Dusk/Night)          ← 게임플레이 훅(이산)
                        │
플레이어 위치 ──▶ ClimateZone[] (씬 볼륨, 각자 ClimateProfile 참조)
                        │  위치 → 존별 weight 정규화(경계에서 두 프로필 블렌드)
                        ▼
                 EnvironmentController (MonoBehaviour, 씬당 1개, Update마다)
                   = blend(zones) ⊗ WorldClock(계절·시간대)
                        ▼
   적용: Directional Light(각도·색·강도) · RenderSettings(ambientLight·fog color/density)
        · Skybox tint/exposure · 달 오브젝트 · [데모] 밤 가로등 그룹 on/off
```

### 3-1. `WorldClock` — 순수 계산 API (저장 없음)

```csharp
// Scripts/World/WorldClock.cs
using System;

public enum Season   { Spring, Summer, Autumn, Winter }
public enum DayPhase { Dawn, Day, Dusk, Night }

public static class WorldClock
{
    // 테스트/오버라이드용 시간 주입점. null이면 실시간.
    public static Func<DateTime> NowProvider = () => DateTime.Now;
    static DateTime Now => NowProvider();

    // ── 계절 ──────────────────────────────────────────
    public static Season CurrentSeason => SeasonOfMonth(Now.Month);

    static Season SeasonOfMonth(int m) =>
        (m >= 3 && m <= 5)  ? Season.Spring :
        (m >= 6 && m <= 8)  ? Season.Summer :
        (m >= 9 && m <= 11) ? Season.Autumn : Season.Winter;

    /// <summary>인접 계절과의 크로스페이드. (from, to, t) — 경계 ±BlendDays에서만 t>0.</summary>
    public static (Season from, Season to, float t) SeasonBlend()
    {
        // 이번 달의 일(day)과 계절 경계까지 남은 일수로 t 계산.
        // 경계 마지막 BlendDays 구간에서 다음 계절로 0→1 선형 보간.
        // 경계 밖이면 (from==to, t==0). 상세 수치는 구현 시 확정.
        ...
    }
    const int BlendDays = 6;

    // ── 하루 ──────────────────────────────────────────
    /// <summary>자정=0, 정오=0.5 … 0~1.</summary>
    public static float DayFraction =>
        (float)(Now.TimeOfDay.TotalHours / 24.0);

    /// <summary>연속 태양 고도각 등 계산에 사용(구현 시 곡선 확정).</summary>
    public static float SunAltitudeDeg => /* DayFraction → 고도각 매핑 */ 0f;

    /// <summary>이산 버킷 — 게임플레이 훅의 단일 진입점.</summary>
    public static DayPhase CurrentPhase
    {
        get
        {
            int h = Now.Hour;
            if (h >= 5  && h < 8)  return DayPhase.Dawn;
            if (h >= 8  && h < 17) return DayPhase.Day;
            if (h >= 17 && h < 20) return DayPhase.Dusk;
            return DayPhase.Night;
        }
    }
    public static bool IsNight => CurrentPhase == DayPhase.Night;

    // ── 개발자 오버라이드(검증용) ──────────────────────
    // 특정 계절/시간대를 강제하려면 NowProvider를 원하는 DateTime 반환으로 바꾼다.
    // 예) WorldClock.NowProvider = () => new DateTime(2026,1,15, 22,0,0); // 겨울·밤
    public static void ClearOverride() => NowProvider = () => DateTime.Now;
}
```

> 핵심: **모든 값이 `Now`의 순수 함수**. 저장/복원·틱 누적이 전혀 없다. 테스트와 개발자
> 오버라이드는 `NowProvider` 하나만 바꿔 겨울·밤 등 임의 상태를 재현한다.

### 3-3. `ClimateZone` — 프로필이 적용되는 씬 구역 + 위치 가중치

```csharp
// Scripts/World/ClimateZone.cs
using UnityEngine;

/// 씬에 배치하는 영역. 플레이어와의 위치 관계로 가중치를 낸다(경계 블렌딩).
public class ClimateZone : MonoBehaviour
{
    public ClimateProfile profile;
    public float innerRadius = 120f;   // 이 안이면 weight=1
    public float outerRadius = 200f;   // 이 밖이면 weight=0, 사이는 선형

    /// <summary>플레이어 위치 → 0~1 영향도.</summary>
    public float WeightAt(Vector3 pos)
    {
        float d = Vector3.Distance(
            new Vector3(pos.x, 0, pos.z),
            new Vector3(transform.position.x, 0, transform.position.z));
        if (d <= innerRadius) return 1f;
        if (d >= outerRadius) return 0f;
        return 1f - (d - innerRadius) / (outerRadius - innerRadius);
    }
    // (원형 대신 Box 볼륨이 필요하면 outerRadius 로직만 교체)
}
```

### 3-4. `EnvironmentController` — 시계+존 블렌드를 Unity에 적용 (씬당 1개)

```csharp
// Scripts/World/EnvironmentController.cs
using UnityEngine;

public class EnvironmentController : MonoBehaviour
{
    public Light sun;                     // 메조리아 Directional Light
    public Transform moon;                // (선택) 밤 달 오브젝트
    public GameObject[] nightLights;      // [데모] 밤 가로등·건물 조명 그룹

    Transform _player;
    ClimateZone[] _zones;

    void Start()
    {
        _zones  = FindObjectsByType<ClimateZone>(FindObjectsSortMode.None);
        _player = /* PlayerRuntime/카메라 타깃 등에서 획득 */ null;
    }

    void Update()
    {
        // 1) 존 가중치 정규화 → 블렌드된 ClimateProfile.EnvKey 산출(계절 반영)
        //    - WorldClock.SeasonBlend()로 인접 계절 EnvKey도 크로스페이드
        // 2) WorldClock.DayFraction/SunAltitudeDeg → 태양 각도·색·강도
        //    - 존이 1개(메조리아)면 블렌드는 그 프로필 그대로
        // 3) 적용:
        //    sun.transform.rotation = ...; sun.color = ...; sun.intensity = ...;
        //    RenderSettings.ambientLight = ...; RenderSettings.fogColor/fogDensity = ...;
        //    Skybox material tint/exposure = ...; moon on/off;
        // 4) [데모 훅] bool on = WorldClock.CurrentPhase is Dusk or Night;
        //    foreach (var g in nightLights) g.SetActive(on);
    }
}
```

- **존이 1개면** 블렌딩은 그 프로필을 그대로 쓰고, 존이 여러 개(향후 대륙 추가)면 자동으로
  위치가중 블렌드가 발동한다 — **v1은 메조리아 존 1개만 배치**.
- Update 부하: 실시간 기준 태양은 분당 ~0.25° 수준으로 매우 느리게 변하므로 매 프레임
  갱신해도 무해. 필요 시 0.2초 간격 타이머로 스로틀 가능(엣지케이스 참조).

### 3-5. 개발자 오버라이드(검증용)

- 가장 단순: 에디터/개발 빌드에서 디버그 키로 `WorldClock.NowProvider`를 특정 `DateTime`으로
  교체(예: `F5`=겨울밤, `F6`=여름낮, `F7`=`ClearOverride()`).
- 또는 `AdminPanel` 커맨드 탭에 "계절/시간대 강제" 버튼 몇 개(선택). 정식 기능 아님이므로
  구현 부담 낮은 쪽 택1. **검증 편의를 위해 최소 하나는 반드시 둔다.**

## 6. 엣지 케이스 / 주의점

- **자정 경계**: `DayFraction`은 자정에 1→0으로 되돌아간다. 태양각 매핑을 순환(0=24시)로 처리해
  자정에 각도가 튀지 않게 한다.
- **계절 경계(월 변경)**: 하드 스냅이면 팔레트가 툭 튄다 → `SeasonBlend()`로 경계 ±6일
  크로스페이드. 경계 밖에서는 t=0(현재 계절만).
- **존 0개/누락**: 씬에 `ClimateZone`이 없으면 `EnvironmentController`는 안전한 기본
  프로필(또는 무동작)로 폴백 — NRE 방지.
- **존 다수 & 플레이어 참조**: 플레이어 Transform 획득 실패 시 카메라 위치로 폴백. 매 프레임
  `FindObjectsByType` 금지 — `Start()`에서 1회 캐시.
- **기존 고정 조명과의 충돌**: `AdjustLighting()`이 남아 있으면 컨트롤러 값과 매 씬 빌드마다
  경합한다 → **반드시 제거/이관**. 초기값은 프로필로 이사.
- **성능**: 실시간 태양은 극도로 느리게 변하므로 매 프레임 재계산이 아깝다면 0.2초 스로틀.
  단 개발자 오버라이드 전환 시엔 즉시 반영(스로틀 무시 1틱).
- **셀셰이딩(11) 이후**: 향후 URP 툰 셰이더/외곽선 적용 시 조명 파이프라인이 바뀔 수 있음 →
  `EnvironmentController`는 "라이트+RenderSettings"라는 표준 채널만 건드려 셀셰이딩과 공존
  가능하도록 유지(프로필에 툰 램프 확장 여지는 후속).
- **날씨 확장점**: `ClimateProfile`에 날씨 필드를 빈 채로 둔다. 후속에서 교역폭풍·증명눈 등
  파티클을 프로필별로 얹고 `EnvironmentController`가 on/off.
- **시간 조작 허용**: v1은 13/12와 동일하게 클라이언트 `DateTime.Now` 신뢰. 서버 검증은 범위 밖.

## 7. 검증 방법

### EditMode 테스트 (`WorldClockTests.cs`)
- `NowProvider`를 3/6/9/12월로 주입 → `CurrentSeason`이 봄/여름/가을/겨울인지.
- 04:59/05:00/07:59/08:00/16:59/17:00/19:59/20:00시 주입 → `CurrentPhase` 버킷 경계 정확성.
- 계절 경계일(예: 5월 27~31일) 주입 → `SeasonBlend()`의 (from=Spring,to=Summer,t 증가) 확인.
- 자정(00:00)·정오(12:00) 주입 → `DayFraction`≈0 / ≈0.5 확인.

### 인게임 (PowerShell 스크린샷 — game-verification 메모리)
1. `MSRPG > Setup Mesoria Scene` 재빌드 → `EnvironmentController`·메조리아 존 배치 확인.
2. 개발자 오버라이드로 **여름 낮** → 밝은 지중해 톤, 가로등 off.
3. **여름 밤/저녁** → 어두워지고 **가로등·건물 조명 on**.
4. **겨울 낮** → 창백·푸르스름, 낮이 짧은 톤.
5. **봄/가을** → 각 팔레트 스크린샷.
6. 오버라이드 해제 → 실제 현재 시각과 일치하는지.
- (후속) 타 대륙 존 추가 후 경계를 걸어가며 하늘·빛이 서서히 블렌드되는지 스크린샷.
