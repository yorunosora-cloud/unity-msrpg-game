## 설계 결정

1. **개념 문제는 `ProblemDef`가 아니라 `ConceptQuestion` 구조체로 `CharacterDef`에 둔다.** 원안(§3-8)은 문제마다 `ProblemDef` 에셋 + `ProblemDatabase` 재구성을 요구하지만, 개념 문제는 캐릭터 1:1 4지선다라 별도 DB·관리자 탭이 필요 없다. `ProblemDef.unlockOwnerId`는 추가하지 않는다. 관리자 편집이 필요해지면 그때 `ProblemDef`로 승격한다.
2. **정답 처리는 `RnEPanel`이 아니라 도감 상세 안에서 한다.** 심화 해설이 잠긴 자리에 문제와 선택지 버튼을 바로 보여 주고, 정답이면 `OwnedCharacter.advancedCodexUnlocked = true`, 저장, 상세 갱신. 오답은 불이익 없이 다음 문제(여러 개면 순환)로 넘어간다.
3. **문제가 없는 캐릭터는 심화 해설을 잠그지 않는다**(영구 잠김 방지). 소유하지 않은 캐릭터는 기존대로 `???`.
4. **CSV `character_codex.csv`**: 한 캐릭터에 여러 행 가능(같은 `ownerId`). 교육 문구(`basicExplanation` 등)는 **한 행에만** 적고(중복 정의는 오류), 각 행이 개념 문제 1개와/또는 호감도 질문 1개를 더한다. 정답·성향 번호는 **1부터 시작**(사람이 읽기 쉽게).
5. **콤보 보상**: `ComboReward.Award(wallet, element)` + 상수 `ComboBonusAmount`(튜닝값). P6의 `SynergyResolver`가 성공 시 이 함수를 호출하게 한다.
6. **호감도 질문**: `AffinityQuestion { question, choices[], conceptPick }` + `IsConceptPick(choice)`. 10번이 `AffinityService.Change(…, Study, …)`로 가산하는 부분은 그쪽 구현 몫.
