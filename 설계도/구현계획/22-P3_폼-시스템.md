# 22 P3 구현 계획 — 폼 시스템 + 플레이어 스턴·둔화

> 근거: `설계도/22_전투-시스템-확장.md` §4-6, **§4-6-1(폼 규칙 확정)**, §4-12, **§4-13(플레이어 스턴·둔화 확정)**. 선행: P2 완료.
> 방식: TDD(빨강→구현→초록→커밋). 테스트 `-testPlatform PlayMode`. 기준선 **320개 중 318 통과**(기존 `SkillProgressTests` 2건 실패는 P3와 무관).
> 범위 밖: 18번 CSV 임포터(P5와 함께), 씬 재생성, 폼 아트/모션. 예시 폼 데이터는 **테스트 코드에서 생성**(하이드리아·카르보나·옥시아·루미에르·에네르기아·마시오 규칙).

**목표:** 캐릭터가 폼을 갖고(스탯·role·gender·tint), 폼 전환 7유형(수동 토글·순차·허브·상태연동·자동 3종)이 §4-6-1 규칙대로 동작하며, 플레이어가 스턴·둔화에 반응한다.

## 설계 보완(계획 단계에서 발견)

| 발견 | 처리 |
|---|---|
| `FormChangeSpec.revertAfterSeconds` 하나로는 수소(삼중수소만 자동 복귀, 경→중은 복귀 없음)를 표현 못 함 | `autoRevertForms[]` 추가: 이 폼에 **진입**하면 복귀 타이머 시작(비면 `toForm`). 설계도 §4-6-1에 반영 |
| Toggle의 양방향 표현이 모호 | Toggle은 `sequence`에 **정확히 2개 폼**을 두고 누를 때마다 다른 쪽으로 전환 |
| 플레이어 이동은 `spd` 스탯과 무관한 고정값(걷기 3·달리기 9) | 에네르기아 `SpeedRatio = 수평속도 / runSpeed`. 문서의 "최대 이동속도(spd)"를 이 정의로 대체 |
| `StatGrowth.ComputeStats(def, level)`는 `def.baseStats` 1개만 읽음 | `ComputeStats(def, level, formId)` 오버로드 추가(폼 없으면 기존 동작) |
| 이동·점프 상태가 `PlayerController` private | `PlayerRuntime.Motion`(`CombatMotionState`)을 매 프레임 갱신 |
| `RecentlyHit(3초)` 판정에 마지막 피격 시각 필요 | `CombatCharacter.SecondsSinceHitTaken` 추가(`TakeHit`이 0으로) |
| 던전·모험 진입/이탈 코드가 아직 없음 | `Party.ResetCombatState()` 메서드와 전멸(`RestoreAll`) 연결까지만. 구역 진입·이탈 호출은 해당 시스템 구현 때 연결 |

## 단계

### A — 순수 코어 (Unity 의존 최소)
- A1 `Meta/FormTypes.cs`: `CharacterForm`(formId·nameKo·role·gender·baseStats·tint·isDefault), `FormChangeMode`, `FormStateCond`, `FormStateRule`, `FormChangeSpec`(+`autoRevertForms`), `FormAutoCond`, `FormAutoRule`, `CharacterForm`. `CharacterDef`에 `forms[]`·`autoRules[]`, `SkillDef`에 `formChange` 필드
- A2 `FormMath.CarryOver`(HP/MP 비율 이월, 생존 시 HP 최소 1) — `FormMathTests`
- A3 `CombatMotionState`(speedRatio·isMoving·isAirborne·verticalSpeed) + `IEnemyAttributes`
- A4 `FormChangeResolver.Resolve(spec, currentForm, defaultForm, ctx)` — Toggle/Sequential/Hub/StateBased 규칙, 재입력 복귀(`pressAgainReverts`) — `FormChangeResolverTests`
- A5 `FormAutoEvaluator`(조건 7종·우선순위·정지/이동 지속 카운터·연속 타격 카운터·`minHoldSeconds=0.25`·`OnSwitchIn` 초기화) — `FormAutoEvaluatorTests`

### B — CombatCharacter 폼 상태
- B1 `StatGrowth` 폼 오버로드, `CombatCharacter`가 현재 폼 기준으로 `MaxHp/MaxMp/Atk/Def/Role/Gender/TintColor/FormNameKo` 계산(폼 없으면 기존 동작·기존 테스트 통과)
- B2 `CurrentFormId`(실제 값)·`ChangeForm(to, cause)`(HP·MP 비율 이월, 쿨타임·상태 유지)·`OnFormChanged` 이벤트·`OnChanged("form")`
- B3 `TryFormChange(keyIndex, recentlyHitWithin…)`: 스턴·기절 차단, 해금·mp·쿨타임 처리(재입력 복귀는 mp 무소모·쿨타임만), `IndexForSlot` 보완(슬롯 0에서 `FormChange` 제외, `formReq` 쉼표 복수)
- B4 `TickForm(dt, motion)`: 자동 복귀 타이머(활성일 때만)·자동 전환 평가(활성일 때만)·`SecondsSinceHitTaken`. `OnSwitchIn` 시 평가 카운터 초기화
- B5 기절 시 기본 폼 복귀, `RestoreFull`/`Party.ResetCombatState()`(상태·스택·폼 초기화, HP·MP·쿨타임 유지) — `CombatFormTests`

### C — 입력·모션·HUD
- C1 `PlayerController`가 `PlayerRuntime.Motion` 갱신
- C2 `PlayerSkills`: `Z`/`X` 폼 전환 키, `active.TickForm` 호출
- C3 `PartyController`: `OnFormChanged` → 틴트 갱신. `PartyHud`/`SkillBarHud`가 폼 변경 시 갱신되는지 확인(필요 시 이벤트 구독 보완)
- C4 통합 테스트 `FormInputTests`(InputTestFixture): Z로 순차 전환, 산소 허브 Z/X·재입력 복귀, 자동 복귀 시간 경과, 대기 중 복귀 타이머 정지

### D — 플레이어 측 스턴·둔화 (§4-13)
- D1 스턴 중 이동·Q·스킬·Z/X·파티 전환 차단(`PlayerController`·`PlayerCombat`·`PlayerSkills`·`PartyController`), 기절 자동 교체는 유지
- D2 `MoveSpeed` 배율을 이동속도에 반영(최소 30% 바닥), `CooldownRate`를 `Party.Tick` 쿨타임 감소에 반영
- D3 통합 테스트 `PlayerStunTests`

### E — 마무리
- 설계도 22: P3 완료 표시, §4-6-1 `autoRevertForms`·Toggle·SpeedRatio 보완 반영, 메모리 갱신, push
