# 18-A 구현 계획 — 속성 · 강점 태그 · 정밀 처치 (22번 P5 포함)

> 근거: `설계도/18_캐릭터-스키마-확장.md` §3-4·3-6·3-9·3-10과 **§8 구현 개정(2026-11-22)**, `설계도/22_전투-시스템-확장.md` §4-4·§4-8. 선행: 22번 P4 완료.
> 방식: TDD(빨강→구현→초록→커밋), `-testPlatform PlayMode`. 기준선 **463개 중 461 통과**(기존 `SkillProgressTests` 2건 실패는 무관).
> 범위 밖: CSV·임포터(18-B), 2단 도감·개념 문제·콤보 보상·호감도(18-C), 시너지 `markId`(P6), 씬 변경.

**목표:** 적이 물리량 속성(질량·속도·온도·전하)을 갖고, 스킬의 강점 태그가 그 값을 읽어 연속적인 피해 배율을 만들며, 막타의 정밀도가 처치 보상 등급을 결정한다.

## 설계 보완(계획 단계 확정)

| 항목 | 결정 |
|---|---|
| 강점 태그 배율 위치 | `HitPipeline.Apply`에서 `atk' = baseAtk × hitMult × formula × **tagMult**`. 오버로드를 만들지 않는다 |
| 태그 사전 접근 | `TagRuleTable.Current`(정적): `Resources.Load<TagRuleTable>("TagRuleTable")` 지연 로드, 테스트는 `TagRuleTable.SetForTests(rules)`/`ResetForTests()`로 주입 |
| 태그 대상 | `ISkillTarget.Attributes`(`Enemy`는 직렬화 `attributes`+`SetAttributes`, `Boss`는 기본 0). 모르는 `tagId`는 배율 1(무시) |
| 기본기 태그 | 슬롯 0 스킬의 `strengthTags`를 `BasicAttack.Resolve`가 `BasicAttackSpec.strengthTags`로 전달 |
| 정밀 처치 대상 | **모든 처치**(기본기·스킬·도트·패시브 피해). 기준 = 처치 직전 HP와 방어·받는피해배율까지 적용한 **최종 피해**(화면 숫자와 일치) |
| 보상 지급 | `Enemy.Die(gradeMult)`가 `StudyMaterials.Add` 지급량에 곱한다(최소 1 유지). 테스트용 `Enemy.LastKillGrade` 노출 |
| 해금 모델 | `SkillDef.startUnlocked` 추가. `CombatCharacter.IsUnlocked`: `startUnlocked` **또는** `unlockedSkillIds` 포함. 그 캐릭터의 어떤 스킬에도 `startUnlocked`가 없으면 레거시 규칙(인덱스 0번 기본) 유지 |
| `unlockCond` | 이 단계는 **파싱·저장까지만**(`SkillUnlockCondition.Parse`, 알 수 없으면 Always 폴백). 평가(승급·스토리 플래그 조회)는 18-B |

## 단계

### A — 순수 타입·로직
- A1 `AttributeProfile`, `TagRule`(Evaluate·FormulaKo), `TagRuleTable`(SO + 정적 `Current`·테스트 주입), v1 물리 8태그 기본 세트 `TagRuleTable.DefaultPhysicsRules()` — `TagRuleTests`(경계: refValue 이하·이상·capMult 초과, high/low 방향)
- A2 `PrecisionKillGrader`(등급 경계 0%/10%/30%) — `PrecisionKillGraderTests`
- A3 `SkillUnlockCondition.Parse`(정상·오타 폴백), `DerivedQuantity`(운동량·운동에너지) — `SkillUnlockConditionTests`

### B — 스키마·전투 연결
- B1 `SkillDef`: `strengthTags`·`startUnlocked`·`unlockCond`·`skillMotion` 추가, `IsUnlocked` 갱신(레거시 호환)
- B2 `ISkillTarget.Attributes`, `Enemy`(직렬화·`SetAttributes`)·`Boss` 구현
- B3 `HitPipeline`에 `strengthTags` 인자 → `tagMult`. `SkillExecutor`(기존 4종·효과 목록)와 `PlayerCombat`/`BasicAttack`이 태그를 전달
- B4 `Enemy`: 처치 직전 HP·최종 피해로 `PrecisionKillGrader` 계산 → `Die(grade)` 보상 배율·`LastKillGrade`

### C — 통합 테스트·마무리
- C1 `StrengthTagTests`: 고온(900) 적 vs 상온(300) 적 피해 차이, 태그 없는 스킬은 기존과 동일(회귀), 알 수 없는 태그 무시, 기본기 태그, 다중 태그 곱, 보스(속성 0)
- C2 정밀 처치 통합: 정확히 HP만큼(±0)·오버킬 5%·50% 처치 → 등급 2.0/1.5/1.0, 도트 막타
- C3 설계도 18 §8·22 §4-8 완료 표시, 메모리 갱신, push

## 완료 기준
- 강점 태그 스킬이 대상 속성값에 따라 피해가 연속적으로 변하고(상한 `capMult`), 태그 없는 스킬은 기존과 동일
- 정밀 처치 등급이 ±0=2.0, ≤10%=1.5, ≤30%=1.2, 그 외 1.0으로 계산되어 처치 보상에 반영
- 기존 463개 중 461 통과 유지(기존 실패 2건 외 신규 실패 없음)
