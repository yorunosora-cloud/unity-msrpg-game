# 23-A 구현 계획 — 스킬 카운터(스택·소모·이력) 시스템

> 배경: 물리 캐릭터 17종 이관에서 **원본 의도를 보존하기로** 했다(2026-11-26). 근사로 옮긴 53개 스킬 중 "스킬 전용 스택·카운터" 계열(시스템 A)을 먼저 만든다. 근사 CSV는 시스템이 완성될 때 원본 의도로 교체한다(결정됨).
> 방식: TDD(빨강→구현→초록→커밋), `-testPlatform PlayMode`. 기준선은 이관 4·5묶음 검증 후 확정.

## 목표
스킬이 **이름 붙은 카운터**를 읽고(위력에 반영) 소모하고(전부/일부), 다양한 조건으로 쌓이며, 시간으로 줄어들게 한다. 현재 `StackTracker`는 패시브 한 개가 "적중/피격 시 +1 → 능력치 증감"만 하므로 아래가 불가능하다.

| 막힌 스킬 | 원본 규칙 |
|---|---|
| 콘두카 자유전자→줄열 | 이동 1초마다 +1(최대 5), 정지 2초마다 −1. 줄열은 위력 `1.0+0.1×스택²`, 스택 전부 소모(Lv.3 계수 0.12). 초전도는 획득 속도 2배 |
| 인술리아 유전 분극→절연 파괴 | 피격 시 +1(최대 5), 3초 무피격마다 −1. 절연 파괴는 `0.7+0.25×스택`(Lv.3 0.3), 전부 소모, 5스택일 때만 스턴 2초 |
| 일렉트라 축전→방전 | 이동·조준 시 누적(최대 10, 스택당 +5%). 방전이 소모(Lv.3 상한 12) |
| 일렉트라 교류(AC)→직류(DC) | 교류는 **적에게** 최대 5스택(Lv.3 7). 직류는 `1.8+0.1×AC스택`, 스택 소모. 최대 스택이면 반경 0.5 폭발(공격력×0.8) |
| 액셀 등가속운동 | 이 스킬 적중마다 +10% 누적(최대 5, Lv.3 6), 피격 시 초기화 |
| 자이라 알짜 돌림힘 | 직전 5초간 쓴 **서로 다른 스킬 수** N → `1.0+0.15×N`(최대 5, Lv.3 0.20) |
| 자이라 각가속도 | 8초간 **공격 행동마다** 공격속도 +8% 중첩(최대 5, Lv.3 7) |
| 세미라 온도 의존성 | **피격 또는 스킬 사용 시** 열 +1(최대 5, Lv.3 7), 스택당 전 스킬 피해 +4%, 5초 무행동 시 초기화 |
| 글루온 업쿼크 | 타격마다 2/3 스택(=3타 1사이클), 3타째 크리티컬 ×2.0(Lv.3 2타째) |

## 설계 결정
1. **카운터 = 캐릭터에 붙는 이름 붙은 정수 상태.** `skill_counters.csv`(신규 시트)에서 정의: `counterId, ownerId, maxStacks, milestoneMaxStacks, gainOn, gainAmount, decay, decaySeconds, resetOn`.
   - `gainOn`: `OnHit`(내가 적중) / `OnHitTaken` / `OnSkillCast` / `OnBasicAttack` / `OnAction`(기본기+스킬) / `MovingSecond`(이동 중 1초마다) / `OnSkillHit:<skillId>`(특정 스킬 적중). 쉼표로 복수(열 스택 = `OnHitTaken,OnSkillCast`).
   - `decay`/`decaySeconds`: 기존 `StackDecay`(ResetAfterIdle/DecayOneEvery) 재사용. `resetOn`: `OnHitTaken` 등 즉시 초기화 조건(등가속운동).
   - 규칙은 `StackTracker`를 확장해 재사용(이동 성장·특정 스킬 적중·초기화 조건만 추가). 타이머는 활성일 때만 흐르고 대기 중엔 유지(설계도 22 §4-7 규칙 1과 동일).
2. **스킬이 카운터를 읽는 방법**: `skill_effects.csv`의 `Damage` 행에 열 추가 — `counterId`, `counterMode`(`Linear`: base+perStack×n / `Quadratic`: base+coeff×n²), `counterCoeff`, `milestoneCounterCoeff`, `counterConsume`(`All`/`None`). 위력 배율 계산은 `HitPipeline` 이전에 `SkillExecutor`가 한다.
3. **카운터 조건부 효과**: 효과 행의 `requireCounterFull=true`면 카운터가 가득일 때만 적용(절연 파괴 스턴, 직류 폭발).
4. **카운터 → 능력치**: `skill_modifiers.csv`의 `source=Counter` + `counterId` + `value`(스택당 증분). `MovingRamp` 근사(자유전자·축전)를 이것으로 교체.
5. **적 쪽 카운터(교류→직류)**: 교류는 이미 적 `StatusHolder`의 도트 스택(`maxStacks`)이다. 직류는 그 스택 수를 읽고 소모한다 → `counterId`를 `target:<statusId>`로 쓰면 적 상태 스택을 가리킨다(별도 구조 없이 `StatusHolder.Stacks/Remove` 사용).
6. **사용 이력(알짜 돌림힘)**: 카운터 `type=DistinctSkills, windowSeconds=5`. 시전 시 (스킬 id, 시각)을 기록하고 창 안의 서로 다른 id 수가 값.
7. **공격 행동 중첩(각가속도)**: 버프 지속 중에만 `OnAction`으로 쌓이고, 쌓인 수 × 8% 가 `CooldownRate`에 곱해진다(버프 종료 시 초기화).
8. **획득 속도 배율(초전도)**: 카운터 정의에 `gainMultiplierStat`을 두거나, 초전도 버프가 `CounterGain`을 2배로 만드는 상태값을 가진다 → 구현은 `StatKind.CounterGain` 신설(기본 1).
9. **HUD**: 카운터 값은 파티 슬롯/스킬 바에 작은 숫자로 표시(별도 단계 D에서, 이번엔 데이터·로직 우선).

## 결정이 필요한 값(문서에 없음 — 제안값, 확인 요청)
- 축전: **조준 개념이 없으므로 이동 중 1초마다 +1**로 구현, 최대 10, 정지 시 감소 없음(방전이 소모). 문서의 "조준 시 누적"은 조준 시스템이 생기면 추가.
- 교류 지속시간: 6초(이미 임시값). 스택마다 갱신.
- 열 스택/자유전자 등의 위치: HUD는 숫자 텍스트로 시작.

## 단계
### A — 카운터 코어(순수 로직)
- A1 `SkillCounter`(순수): 증가·감소·초기화·소모·마일스톤 상한. `StackTracker` 확장 또는 병행. 테스트 `SkillCounterTests`.
- A2 `DistinctSkillWindow`(순수): N초 창 안 서로 다른 스킬 수.
- A3 위력 공식: `Linear/Quadratic` 계산 헬퍼.

### B — 캐릭터 통합
- B1 `CombatCharacter`에 카운터 컨테이너. 이벤트 연결: 적중·피격·스킬 시전·기본기·이동 틱·폼 전환. 기절/전투 이탈 시 초기화.
- B2 `SkillExecutor`: `Damage` 행의 counter 열 처리(읽기·소모), `requireCounterFull`, 적 상태 스택 읽기/소모.
- B3 카운터→능력치 수정자(`source=Counter`), `StatKind.CounterGain`.

### C — 데이터·임포터
- C1 `CharacterCsvBuilder`: `skill_counters.csv` 시트, effects/modifiers 신규 열, 검증(없는 counterId·owner 불일치).
- C2 해당 9개 스킬을 원본 의도로 갱신(근사 CSV 교체), `gameNoteKo` 정리, `ShippedCsvTests` 갱신.

### D — 표시
- D1 카운터 값 HUD 표기.

## 완료 기준
- 위 9개 스킬이 원본 수치대로 동작하고 단위 테스트로 검증된다(줄열 5스택 = 3.5배 등).
- 기존 테스트 유지(알려진 실패 2건 제외).
- 근사했던 `gameNoteKo`가 정리되고 설계도 18 §8-5·§8-7에 결과가 기록된다.
