# 22 P4 구현 계획 — 패시브 (3경로) + 마일스톤 교체값

> 근거: `설계도/22_전투-시스템-확장.md` **§4-7(패시브 확정)**, §4-3(마일스톤 교체값 확정), §4-12. 선행: P3 완료.
> 방식: TDD(빨강→구현→초록→커밋), `-testPlatform PlayMode`. 기준선 **394개 중 392 통과**(기존 `SkillProgressTests` 2건 실패는 P4와 무관).
> 범위 밖: 18번 CSV 임포터·P5 속성(적 속성값), 씬 재생성, 패시브 HUD 아이콘. 패시브 데이터는 **테스트 코드에서 생성**(캐릭터 문서의 대표 패시브로 검증).

**목표:** 패시브 23개가 쓰는 세 경로(이벤트·상시 수정자·타격 공식)를 §4-7 규칙대로 동작시킨다.

## 설계 보완(계획 단계에서 발견)

| 발견 | 처리 |
|---|---|
| 적중·피격 이벤트가 코드에 **없음**(`ReceiveHit`/`TakeHit`이 이벤트를 안 냄) | `HitInfo` + `CombatCharacter` 이벤트(`OnHitDealt`/`OnHitTaken`). 공격 행동(기본기·스킬)이 끝나면 `NotifyHits`로 일괄 발행, 피격은 `TakeHit(damage, attacker)` |
| 적에게 `spd`·이동 방향 없음(크로노 γ·도플러 입력) | `Enemy.Spd`(직렬화, 기본 0)·`Enemy.ApproachSign(playerPos)`(프레임 위치 변화로 접근/후퇴 부호) |
| 적 `Mark`는 속성만 보관(id·지속시간 없음) | `Enemy`에 id별 마크(지속시간·소유자) — `Mark(id, owner, duration)`·`HasMark`·`MarkAge`. 기존 `SetMark(Continent)`는 호환 유지 |
| 패시브 스킬도 `slot`을 가져 `IndexForSlot`이 키 입력으로 잡을 수 있음 | `IndexForSlot`에서 `skillType == Passive` 제외(폼 전환 스킬과 같은 처리) |
| 운동량 "가한 피해의 10%만큼 공격력 증가"는 고정 스택값이 아님 | `StackSpec.damageRatio` 추가: 증가량 = 가한 피해 × ratio ÷ 기본 공격력(상한 `maxStacks × perStackValue` 대신 `cap`) |
| 월드에 효과를 내야 함(광역 피해·넉백·텔레포트·마크) — `CombatCharacter`는 순수 클래스 | **`PassiveRunner`(순수)**가 스택·수정자·자신 대상 효과를 처리하고, 월드 효과는 `PassiveFire`로 발행 → **`PassiveHost`(MonoBehaviour)**가 실행. `PlayerSkills.Awake`가 `PassiveHost`를 자동 추가(씬 변경 없음) |
| 질량 오라(적 이동속도 −15%, 반경 6.0)는 지속 적용 | `PassiveHost`가 매 프레임 반경 내 적에게 0.3초짜리 둔화를 갱신(`aura:<id>`), 범위를 벗어나면 자연 소멸 |
| 파티 존재 수정자(고유 시간·전자기력)는 대기 캐릭터에도 적용 | `Party`가 `partyWide` 수정자를 모아 전원에게 공급(같은 id 1회만, 규칙 9) |
| `Teleport`는 `CharacterController` 이동이라 단순 대입 불가 | `PassiveHost`가 `CharacterController`를 잠시 끄고 위치 설정 |
| `HpBelowPercent` 에지 판정에 이전 HP 비율 필요 | 러너가 직전 비율을 기억, 임계를 위→아래로 넘는 순간만 발동 |

## 단계

### A — 순수 코어
- A1 타입: `PassiveTriggerType`·`HitCountMode`·`StackDecay`·`PassiveFormulaId`·`ModifierSource`·`StackSpec`·`PassiveModifierSpec`·`PassiveSpec`, `SkillDef.passive`, `TargetScope.HitTarget/Attacker`, `SkillEffectType.Teleport`, `StatKind.SkillPower/HitDamage`, `StatusEffect.ConsumeOnHit`, `SkillEffectEntry.areaRadius/milestoneValue/milestoneDuration`
- A2 `PassiveFormula`(Lorentz·Doppler(클램프 0.33~3.0, 범위 ÷D)·RangeWork·AxisDistance) — `PassiveFormulaTests`
- A3 `StackTracker`(최대·ResetAfterIdle·DecayOneEvery·ConsumeAtCap·활성일 때만 흐름·대기 시 유지) — `StackTrackerTests`
- A4 `ModifierEvaluator`(Constant·LostHpPercent·MovingRamp(상승·감소)·PartyPresence) — `ModifierTests`
- A5 `HitInfo`·`CombatAnchor`(5초 비전투 후 교전 시작 위치) — `CombatAnchorTests`

### B — PassiveRunner·CombatCharacter 통합
- B1 `PassiveRunner`: 활성 패시브 선별(해금·`formReq`·폼), 이벤트 라우팅(OnHit 행동당/대상당, 도트·패시브 유발 피해 제외, OnHitTaken, OnFormChange, HpBelowPercent 에지+내부 쿨타임, SelfDebuffed)
- B2 자신 대상 효과는 `AllyEffectApplier`로 직접 적용, 스택은 `StatusEffect`/`StackTracker`로 능력치에 반영, `ConsumeOnHit`(가속도·양자화)
- B3 `CombatCharacter`: `StatMult(StatKind)`(= `Status` × 패시브 수정자 × 파티 존재), `Atk/Def/MoveSpeedMultiplier/TakeHit/Party.Tick(CooldownRate)`가 이를 사용, `OnHitDealt/OnHitTaken` 이벤트, `TakeHit(damage, attacker)`, `NotifyHits`, `ChangeForm`→`OnFormChange`
- B4 `IndexForSlot`에서 패시브 제외, `Party` 파티 존재 수정자 공급(중복 id 1회)
- B5 마일스톤: `SkillScaling`이 교체값(`milestoneValue/Duration`, `StackSpec.milestone*`, `PassiveModifierSpec.milestone*`) 적용 — `PassiveRunnerTests`

### C — 월드 연결
- C1 `Enemy`: `Spd`·`ApproachSign`·id별 마크(지속시간·소유자) — 기존 `SetMark` 호환
- C2 `PassiveHost`: `PassiveFire` 실행(광역 피해(`areaRadius`)·넉백·마크·텔레포트+정화·반사 피해·질량 오라)
- C3 타격 경로에 이벤트·공식 삽입: `PlayerCombat`(기본기)·`SkillExecutor`(기존 4종 + 효과 목록)가 `passiveHitMult`를 곱하고 `NotifyHits` 발행
- C4 피격 경로: `Enemy` 접촉 공격 → `TakeHit(damage, this)`
- C5 `PlayerSkills`: `PassiveRunner.Tick(dt, isActive, motion)`·`PassiveHost` 자동 추가 — 통합 테스트 `PassiveWorldTests`

### D — 마무리
- 설계도 22: P4 완료 표시, 보완(`StackSpec.damageRatio`·`PassiveHost` 등) 반영, 메모리 갱신, push
