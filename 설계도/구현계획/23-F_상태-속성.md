# 23-F 구현 계획 — 상태·속성

> 근거: 이관 근사 목록(우력·탑쿼크·자기장·전자기력·정전기 차폐·스트레인지 쿼크 ①). 방식: TDD, `-testPlatform PlayMode`.

## 목표(원본 규칙)
| 스킬 | 원본 규칙 | 필요한 것 |
|---|---|---|
| 자이라 우력 | 적중한 적의 이동방향 반전 2초(Lv.3 3초) | 반전 상태이상 |

| 인술리아 정전기 차폐 | 받는 피해 −35% + **전기 속성 피해 면역** | 속성별 피해 감소(면역) |
| 마그놀 전자기력 | 전기 속성 아군 공격력 +20%, 그 외 +7% | 아군 속성 + 수정자 조건 |
| 글루온 스트레인지 쿼크 ① | 상대 공격의 속성을 무작위로 바꿈 | 속성 무작위 변경 |

## 설계 결정
1. **공격 속성** `AttackElement`(플래그): `Metal / Electric / Thermal / Light`. 적은 `attackElement`(직렬화, 기본 None), 아군은 `CharacterDef.attackElement`(CSV `character_catalog.attackElement`).
   - **전기 속성 아군(사용자 결정):** 일렉트라·콘두카·세미라·인술리아·마그놀.
   - 적의 속성 값은 17번 적 도감 단계에서 채운다(지금은 전부 None → 속성별 효과는 데이터가 생기면 작동).
2. **속성 한정 상태 효과**: `StatusEffect.ElementMask`/`ElementInvert`. `Mult(stat, element)` — 마스크가 있으면 공격 속성이 맞을 때만(반전이면 맞지 않을 때만) 적용. 속성을 모르는 경우(None)는 반전 효과("그 외")에만 적용.
3. **피해 처리**: `TakeHit`이 공격자의 `AttackElement`로 `DamageTaken` 배율을 계산한다.
4. **수정자 조건**: `PassiveModifierSpec.requireElement`/`requireElementInvert` — 파티 존재 수정자를 받는 **아군의 속성**으로 걸러 적용한다.
5. **효과 3종**: `ReverseMove`(적 이동방향 반전, duration), `Dispel`(대상의 이로운 상태 제거), `RandomizeElement`(공격 속성을 무작위 속성으로).
6. CSV: `skill_effects`(`elementMask·elementInvert`), `skill_modifiers`(`requireElement·requireElementInvert`), `character_catalog`(`attackElement`). 검증: 알 수 없는 속성 이름은 오류.

## 단계
A 순수 속성·상태 로직 → B 전투 연결(TakeHit·파티 수정자·효과 3종) → C CSV·임포터 → D 6개 스킬 데이터 교체.
