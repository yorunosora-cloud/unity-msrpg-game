# 13. 출석 시스템

> 최초의 **일일 리셋(daily reset) 시스템**. 이 설계에서 확립하는 `DailyResetHelper`는
> 향후 10 호감도·12 상점의 날짜 리셋 로직이 채택할 canonical 패턴이다.

---

## 세계관 맥락

- **배움의 전당 출석부(AttendanceLedger)** — 메조리아에 매일 등원하면 학사 일지에
  기록이 남고, 꾸준함에 대한 보상(연구 지원금·집중력)이 지급되며, 특히 한 주를
  꽉 채운 날에는 지식의 탐구 재원(논문/책)이 두둑이 쌓인다. 논문을 들여 밀린
  등원을 소급 기록(보충)할 수도 있다. "매일의 배움이 곧 성장"이라는 세계관을
  강화하는 공간.

---

## 1. 목표 / 완료 정의

1. **자동 진입**: 메조리아 첫 접속 시 그날 미수령이면 `AttendancePanel` 자동 오픈.
2. **오늘 출석**: [오늘 출석] 클릭 → 이번 달 누적 칸 +1, 해당 칸 보상 즉시 지급,
   당일 재수령 불가.
3. **누적 상한**: 누적 칸 수는 **오늘까지 지난 일수(day-of-month)**를 넘지 못한다.
4. **논문 보충 (후속)**: 밀린 칸은 논문을 내고 상한까지 따라잡을 수 있다.
   데이터 모델은 이번 설계부터 지원하되, 실제 UI 버튼 연결은 후속 단계.
5. **주기 리셋**: 매달 1일(로컬 날짜 기준) 누적 0부터 재시작.
6. **28칸 달력 UI**: 수령완료(✓) · 오늘 수령 가능 · 보충 가능 · 미래 잠금 상태를
   시각적으로 구분.
7. **저장·복원**: 누적 수·마지막 수령일·주기월이 PlayFab에 저장되어 재로그인 후
   유지된다.

### 확정 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| 1 | 보상 구조 = **월간 달력(누적)**, 스트릭 아님. 매달 1일 초기화 | 이 프로젝트의 핵심 철학인 "학습 위축 방지"(오답 페널티 없음)와 정합. 스트릭은 빠진 날을 벌주지만 누적 달력은 진도만 늦출 뿐 아무것도 소멸시키지 않는다 |
| 2 | 칸 인덱스 = **이번 달 누적 출석 횟수** (달력 날짜 아님) | 빠진 날은 그냥 진도가 늦어질 뿐 |
| 3 | **누적 칸 ≤ 오늘까지 지난 일수(day-of-month)** 상한 | 논문 보충이 "미래 칸 선구매"가 되지 않도록. 놓친 과거만 메울 수 있게 제한 |
| 4 | **논문 보충** — 밀린 칸을 논문 내고 상한 내에서 따라잡기. 데이터 모델은 지금 지원, UI는 후속 | 매일 접속 못 해도 소외감 없이 따라잡을 수 있는 여지를 남김 |
| 5 | 주기 = **28칸 고정** | 2월·월 길이 편차 회피. 하루 1회 → 최대 28보상/월 |
| 6 | 리셋 기준 = **로컬 시간** `DateTime.Now.ToString("yyyy-MM-dd")`, 클라이언트 권위 | 12 상점 설계와 동일 정책, 현재 코드베이스가 서버 시각 검증 인프라를 갖추지 않음 |
| 7 | 공유 유틸 **`DailyResetHelper`** 신설 | 최초 일일 리셋 시스템 → 이후 호감도·상점이 채택할 기준 확립 |
| 8 | 진입 = **메조리아 첫 접속 자동 팝업** + **계정 버튼 옆 상시 버튼**(클릭 재열람) | 자동 팝업으로 놓치지 않게 하고, 상시 버튼으로 언제든 재열람. `AccountPanel.openButton` 패턴 재사용 |
| 9 | v1 보상 = **마일스톤 집중 구조**. 평일 = **균형 혼합**(논문·골드·집중력 소소 순환), 마일스톤(7·14·21·28일) = **가챠 지향**(논문 뭉치, 28일은 논문+결정) | 구현된 재화 획득처가 거의 없고 소비처도 논문→가챠만 실제 작동. 개념조각(Fragment)은 코드상 소비처 0(표시·어드민 지급뿐)이라 v1 보상에서 제외. 평일은 미래 시스템 대비로 골고루, 큰 보상은 실제 작동하는 논문에 집중해 "며칠 더 채우면 대박"이라는 목표 동기 부여 |

## 3. 아키텍처

### 3-1. 공유 유틸 — `DailyResetHelper` (신규, 최초의 일일 리셋 헬퍼)

```csharp
// Scripts/Meta/DailyResetHelper.cs
using System;

public static class DailyResetHelper
{
    /// <summary>로컬 날짜 "yyyy-MM-dd".</summary>
    public static string Today() => DateTime.Now.ToString("yyyy-MM-dd");

    /// <summary>로컬 연-월 "yyyy-MM".</summary>
    public static string ThisMonth() => DateTime.Now.ToString("yyyy-MM");

    /// <summary>이번 달 오늘까지 지난 일수 (1~31). 누적 상한 계산에 사용.</summary>
    public static int DayOfMonth() => DateTime.Now.Day;

    /// <summary>마지막 기록일이 오늘이 아니면 true(새 날짜).</summary>
    public static bool IsNewDay(string lastDate) => lastDate != Today();
}
```

> 이 파일은 출석 시스템 전용이 아니다. 10 호감도의 `AffinityState.CheckDailyReset()`,
> 12 상점의 `ShopDailyState.TryResetIfNewDay()`가 각자 재구현한 로직을 이 헬퍼로
> 대체하는 것을 후속 리팩터로 권장한다 (본 설계도 범위 밖, §6 참고).

### 3-2. 보상 정의 — `AttendanceReward` / `AttendanceCatalog`

```csharp
// Scripts/Meta/AttendanceReward.cs
using System;

// v1 = Currency, Crystal. 확장 예정: Consumable(12 구현 후), EventItem(이벤트 시스템 구현 후)
public enum AttendanceRewardType { Currency, Crystal }

[Serializable]
public struct AttendanceReward
{
    public AttendanceRewardType type;
    public int kindIndex;   // CurrencyKind 또는 CrystalKind의 정수값
    public int amount;
}
```

> **미래 확장 — 이벤트 상품 보상**: 이벤트 시스템 도입 시 이벤트 상품 일부를 출석
> 보상으로도 지급할 예정. 확장 방식은 두 단계다.
> ① `AttendanceRewardType`에 `EventItem` 값을 추가하고 `AttendanceService.Grant`의
>    switch에 케이스 1개만 추가한다(이벤트 아이템 인벤토리로 지급) — `Currency`/
>    `Crystal`과 동일한 패턴이라 확장 비용이 낮다.
> ② `AttendanceCatalog.Get(int)`이 보상표 조회의 단일 진입점이므로, 이벤트 기간에는
>    이 조회를 이벤트용 오버라이드 테이블로 바꿔치기해 특정 칸(특히 마일스톤)이
>    이벤트 상품을 지급하도록 만들 수 있다.
> 이번 설계의 구현 범위는 아니며, 나중에 자연스럽게 얹을 수 있도록 확장점만
> 남겨둔다.

> **평일(비마일스톤) = 균형 혼합**: 논문·골드·집중력 3종을 순환 지급하며, 주차가
> 오를수록 소폭 상승하되 마일스톤보다는 확실히 소소하게 유지한다.
> **마일스톤(7·14·21일) = 가챠 지향**: 논문 뭉치(30/50/80)로 "며칠 더 채우면
> 뽑기 대박"이라는 목표 동기를 만든다. **28일 대박** = 논문 150(10연챠 1회 이상)
> + 결정 ×10(08 승급 재료로서 미래 가치).
> **월 누적 논문 ≈380** (매일 접속 시, 10연챠 약 3.8회분) — 마일스톤에 보상이
> 몰린 구조라 총량이 크다. 밸런싱 시 부담스러우면 마일스톤 수치를 하향한다.
> **개념조각(Fragment)은 v1 보상에서 제외** — 코드상 소비처가 없어(§1 결정 #9
> 참고) 지금 주면 쌓이기만 한다. 이벤트 상점 등 소비처가 생기면 재도입을
> 검토한다.
>
> 28일차는 결정 지급 외에 논문도 함께 지급하는 이중 보상이다. `AttendanceReward`가
> 단일 보상만 표현하는 구조이므로, 구현 시 `AttendanceService.Grant`에서
> `claimedCount == 27`(28일차, 0-index)이면 `AttendanceCatalog.Get(27)`(논문)에
> 더해 `AttendanceCatalog.Day28Bonus`(결정)를 함께 지급하는 특수 분기를 둔다.

### 3-3. 상태 — `AttendanceState`

```csharp
// Scripts/Meta/AttendanceState.cs
using System;

[Serializable]
public class AttendanceState
{
    public string lastClaimDate = "";  // "yyyy-MM-dd" 마지막 무료 수령일
    public string cycleMonth    = "";  // "yyyy-MM" 현재 주기
    public int    claimedCount  = 0;   // 이번 달 누적 수령 칸 (0~28)

    /// <summary>패널 오픈/체크 시마다 호출. 달이 바뀌었으면 리셋.</summary>
    public void SyncCycle()
    {
        string m = DailyResetHelper.ThisMonth();
        if (cycleMonth != m)
        {
            cycleMonth = m;
            claimedCount = 0;
            lastClaimDate = "";
        }
    }

    /// <summary>오늘까지 지난 일수로 계산한 누적 상한 (28 초과 불가).</summary>
    int Ceiling() => Math.Min(28, DailyResetHelper.DayOfMonth());

    /// <summary>무료 "오늘 출석" 가능 여부: 오늘 아직 안 받았고 상한 미만.</summary>
    public bool CanClaimToday() =>
        DailyResetHelper.IsNewDay(lastClaimDate) && claimedCount < Ceiling();

    /// <summary>
    /// (후속) 보충 가능 칸 수: 상한에서 이미 받은 칸과 "오늘 무료 수령분"을 뺀 나머지.
    /// 오늘 무료 수령권은 이 수치에서 제외되어 Makeup이 그것을 대신 소모하지 않는다.
    /// </summary>
    public int MakeupAvailable() =>
        Math.Max(0, Ceiling() - claimedCount - (CanClaimToday() ? 1 : 0));

    public AttendanceData Export() => new AttendanceData
    {
        lastClaimDate = lastClaimDate,
        cycleMonth    = cycleMonth,
        claimedCount  = claimedCount,
    };

    public void LoadState(AttendanceData d)
    {
        if (d == null) return;
        lastClaimDate = d.lastClaimDate ?? "";
        cycleMonth    = d.cycleMonth ?? "";
        claimedCount  = Math.Max(0, d.claimedCount);
    }
}

[Serializable]
public class AttendanceData
{
    public string lastClaimDate;
    public string cycleMonth;
    public int    claimedCount;
}
```

### 3-4. 서비스 — `AttendanceService`

```csharp
// Scripts/Meta/AttendanceService.cs
public static class AttendanceService
{
    /// <summary>무료 "오늘 출석". 성공 시 보상 지급 + 저장.</summary>
    public static bool Claim()
    {
        var s = MetaState.Attendance;
        s.SyncCycle();
        if (!s.CanClaimToday()) return false;

        GrantDay(s.claimedCount); // 0-index = 다음 칸
        s.claimedCount++;
        s.lastClaimDate = DailyResetHelper.Today();
        MetaSaveService.Save();
        return true;
    }

    /// <summary>
    /// (후속 단계에서 UI 연결) 논문 보충. 밀린 칸을 상한 내에서 채운다.
    /// 데이터 모델·로직은 이번 설계부터 지원하되, v1의 AttendancePanel에서는
    /// 버튼을 숨기거나 비활성 상태로 둔다.
    /// </summary>
    public static bool Makeup(int paperCost)
    {
        var s = MetaState.Attendance;
        s.SyncCycle();
        if (s.MakeupAvailable() <= 0) return false;
        if (!MetaState.Wallet.TrySpend(CurrencyKind.Paper, paperCost)) return false;

        GrantDay(s.claimedCount);
        s.claimedCount++;               // lastClaimDate은 갱신하지 않음 — 오늘 무료 수령권 보존
        MetaSaveService.Save();
        return true;
    }

    /// <summary>해당 칸의 보상을 지급. 28일차(claimedCount==27)는 결정 보너스를 병행 지급.</summary>
    static void GrantDay(int claimedCount)
    {
        Grant(AttendanceCatalog.Get(claimedCount));
        if (claimedCount == 27) Grant(AttendanceCatalog.Day28Bonus);
    }

    static void Grant(AttendanceReward r)
    {
        switch (r.type)
        {
            case AttendanceRewardType.Currency:
                MetaState.Wallet.Add((CurrencyKind)r.kindIndex, r.amount);
                break;
            case AttendanceRewardType.Crystal:
                MetaState.Crystals.Add((CrystalKind)r.kindIndex, r.amount);
                break;
        }
    }
}
```

### 3-5. UI — `AttendancePanel` (`AccountPanel` 패턴 복제)

- `Start()`: `openButton` 리스너 연결. `MetaState.Attendance.SyncCycle()` 호출 후,
  **현재 씬이 메조리아이고 `CanClaimToday()`가 true**이면 자동 `Open()`. 다른 씬
  (아틀란티스 등)에서는 자동 오픈하지 않음 — 씬 이름 가드.
- `Open()`은 `AccountPanel`과 동일하게 `UIManager.TryOpen()`을 거쳐 다른 패널과
  중재된다.
- 레이아웃: 7열 × 4행 = 28칸 그리드. 각 칸에 일차 번호·보상 아이콘·수량·상태
  뱃지(✓ 수령완료 / 오늘 수령가능 강조 / 보충가능 / 잠금)를 표시.

## 6. 엣지 케이스 / 주의점

- **월 경계 리셋**: `SyncCycle()`이 `cycleMonth` 불일치를 감지하면 `claimedCount=0`
  + `lastClaimDate=""`로 리셋 → 새 달 첫날 바로 [오늘 출석] 가능.
- **누적 상한**: `Ceiling() = min(28, DayOfMonth())`. 매일 접속하면 상한과 누적이
  같아져 보충 가능분이 0. 며칠 빠지면 그 차이만큼만 보충 가능 — 미래 칸 선구매
  방지.
- **보충과 무료 수령의 분리**: `Makeup()`은 `lastClaimDate`를 변경하지 않는다.
  따라서 오늘 무료 수령권은 보충 여부와 무관하게 유지되며, `MakeupAvailable()`
  계산에서 오늘 무료 수령분(있다면 1칸)을 미리 제외해 이중 계산을 막는다.
- **자동 팝업 씬 가드**: 메조리아 이외 씬(아틀란티스 등)에서는 자동 오픈하지
  않는다. `AttendancePanel.Start()`에서 현재 씬 이름을 확인해 분기.
- **기기 시간 조작 허용 범위**: v1은 12 상점과 동일하게 클라이언트 권위
  `DateTime.Now` 비교를 허용한다. 서버 측 검증(PlayFab CloudScript 타임스탬프)은
  후속 확장.
- **저장 하위호환**: `KEY_ATTENDANCE`가 없는 구세이브는 `JsonUtility`가 빈 DTO로
  역직렬화 → `claimedCount=0`, `cycleMonth=""` → 첫 패널 오픈 시 `SyncCycle()`이
  당월로 자동 초기화. 별도 마이그레이션 불필요.
- **자정 경계에서 상한 갱신**: 패널을 오래 띄워둔 채 자정을 넘기면 `DayOfMonth()`
  기반 상한이 커진다. 패널 오픈 시마다(또는 [오늘 출석] 클릭 시마다) `SyncCycle()`
  을 재호출해 최신 상한을 반영한다 — 캐시하지 않는다.
- **28일차 이중 보상 처리**: `AttendanceReward`가 단일 보상만 표현하는 구조라
  28일차의 "논문+결정" 동시 지급은 `AttendanceService.GrantDay()`가
  `claimedCount==27`일 때 `AttendanceCatalog.Get(27)`(논문)에 더해
  `AttendanceCatalog.Day28Bonus`(결정)를 함께 호출하는 방식으로 해결한다
  (§3-2, §3-4 참고). `Claim()`·`Makeup()` 양쪽 모두 이 공용 경로를 거치므로
  보충으로 28일차를 채워도 동일하게 이중 지급된다.
- **이벤트 보상 확장점**: 이벤트 상품을 출석 보상으로 지급하는 기능은 v1
  범위가 아니지만, `AttendanceRewardType.EventItem` 추가 + `AttendanceCatalog`
  오버라이드 주입으로 자연스럽게 확장 가능하도록 설계했다 (§3-2 미래 확장
  노트 참고). 이벤트 시스템 설계 시 이 확장점을 참조할 것.

## 7. 검증 방법

### EditMode 테스트 (`AttendanceTests.cs`)
- `cycleMonth`를 지난달로 강제 설정 후 `SyncCycle()` → `claimedCount==0`,
  `lastClaimDate==""` 확인.
- 첫 `Claim()` 성공 → `claimedCount==1`, 보상 지급 확인. 같은 날 재 `Claim()` →
  실패.
- `DayOfMonth()`를 넘는 `claimedCount`로 설정 후 `Claim()` 시도 → 상한 때문에
  실패 (day-of-month보다 앞서갈 수 없음 확인).
- `Makeup()`: 밀린 칸이 있을 때 논문 차감 + 보상 지급 + `lastClaimDate` 불변
  확인. `MakeupAvailable()==0`일 때 실패 확인.
- `Export()` → `LoadState()` 왕복 후 세 필드(`lastClaimDate`/`cycleMonth`/
  `claimedCount`) 일치 확인.
- `AttendanceRewardType.Currency`/`Crystal` 각각 올바른 지갑(`Wallet`/
  `Crystals`)에 정확히 지급되는지 확인.
- `claimedCount`를 27로 설정 후 `Claim()` → 논문(카탈로그 28일차 값)과 결정
  (`Day28Bonus`)이 동시에 지급되는지 확인 (`GrantDay` 이중 지급 검증).
