# 21. 던전 레벨 스케일링 & 계정 레벨

> **상태**: 사용자와 대화로 핵심 규칙 확정(2026-11). 세부 수치(구역 보정·보상 배율·EXP 계수)는 **초안**이며
> 밸런스 테스트로 조정한다. **구현 미착수(설계만).**
> **레벨 상한 정책(2026-11 정정)**: 캐릭터 레벨 상한은 **존재**하며 08 승급(니케 "스페어 바디" 방식)으로 단계적으로
> 올라간다. **최종 랭크까지 승급한 캐릭터가 10명 이상이 되면 레벨 상한이 보유 캐릭터 전체·계정 모두에서 해제**된다.
> 따라서 08 승급은 대부분 유지되고 "상한 해제 조건"만 추가된다(§7).

---

## 배경

지금까지 던전은 "권장 레벨 lv22-27"처럼 **고정 레벨**로 설계됐다. 이 방식은 플레이어가 던전 순서를
레벨에 맞춰 따라가야 하고, 후반에 앞 던전을 다시 돌면 시시해진다. 사용자는 **플레이어가 원하는
순서로 던전에 도전**할 수 있도록 하되, 완전 스케일링의 약점(레벨업 동기 약화)을 **진입 하한**으로
보완하는 방식을 확정했다.

핵심 원칙: **"막으려는 게 목적이 아니고 성장이 목적이다. 한도에 못 미치면 어려울 뿐이다."**

---

## 1. 목표 / 완료 정의

- 던전 적·보스의 레벨이 **계정 레벨**에 맞춰 결정되고, 고정 권장 레벨 표기가 사라진다.
- 던전 클리어 순서(몇 번째로 새 던전을 깨는가)에 따라 **진입 하한**이 정해지며, 하한 미만이어도
  입장은 가능하고 경고만 표시된다(적이 하한 레벨로 고정되어 어려워짐).
- **계정 레벨**이 신설되어 문제 풀이·던전/보스 클리어·임무/출석으로 오른다. **해제 전 상한 80, 최종 랭크
  승급 캐릭터 10명 이상이면 상한 해제(무제한).**
- 기존 던전 문서·CSV의 레벨·수치는 **기준값**으로 재해석되어 코드 변경 없이 새 규칙에 흡수된다.

## 4. 아키텍처

### 4-1 계정 레벨 (신설)

```csharp
public class AccountProgress
{
    public int level = 1;
    public long exp;                         // 현재 레벨 내 누적 EXP
    public HashSet<string> clearedDungeons;  // 클리어한 서로 다른 던전 ID (하한 카운트 기준)
}
```

- 저장: 기존 플레이어 저장 레이어(PlayFab UserData 등)에 추가 — 구현 시 기존 저장 패턴 따름.
- **계정 레벨 상한**: 해제 전 80(`LevelCapUnlock.IsUnlocked == false`), 해제 후 없음(`level`은 int).

### 4-1-bis 레벨 상한 전역 해제 (신규)

```csharp
public static class LevelCapUnlock
{
    public const int RequiredMaxRankCount = 10;     // 초안 확정(사용자 승인)
    public const int PreUnlockCap = 80;             // 해제 전 계정 레벨 상한 = UR 캐릭터 상한
    // 최종 랭크(MaxPromotionRank)까지 승급한 보유 캐릭터 수가 10 이상이면 해제
    public static bool IsUnlocked(IEnumerable<OwnedCharacter> owned)
        => owned.Count(o => o.promotionRank >= PromotionTuning.MaxRank(o.def.rarity)) >= RequiredMaxRankCount;
}
```

- 해제는 **한 번 달성하면 영구**(이후 승급 캐릭터 수가 줄어도 되돌리지 않음 — 플래그 저장 권장).
- 해제 효과: ① 모든 캐릭터의 `LevelCap` 무시 ② 계정 레벨 상한 80 해제 ③ 던전 하한이 80에서 계속 증가.

### 4-2 계정 EXP

| 경로 | 지급 시점 | 비고 |
|------|----------|------|
| 문제 풀이(R&E) | 레벨업/스킬 문제 정답 시 | 학습과 성장 직결 — 이 게임의 핵심 |
| 던전·보스 클리어 | 던전 클리어, 신규 던전 최초 클리어 보너스 | 하한을 넘기 위한 압박과 보상 |
| 일일/주간 임무·출석 | 15, 13번 보상에 계정 EXP 항목 추가 | 꾸준한 플레이 보상 |

**필요 EXP 곡선(형태 확정, 계수 초안)**:

```
levelUpExp(L) = A × L^K     // 초안: A = 100, K = 1.3
```

- 지수 곡선(캐릭터 `1.45^L`)을 쓰지 않는다 — 상한이 없는 시스템에서 고레벨 폭발을 막기 위함.
- 신규 던전 최초 클리어는 하한 간격(+4레벨) 만큼의 계정 EXP를 보상으로 주는 방향으로 튜닝.

### 4-3 진입 하한

```
dungeonFloor(n) = 1 + 4 × (n − 1)     // n = 클리어한 서로 다른 던전 수 + 1
```

| 신규 클리어 순번 | 하한 | | 신규 클리어 순번 | 하한 |
|---|---|---|---|---|
| 1번째 | 1 | | 9번째 | 33 |
| 2번째 | 5 | | 16번째 | 61 |
| 3번째 | 9 | | 24번째 | 93 |
| 4번째 | 13 | | 32번째(예상 마지막) | 125 |

- **해제 전에는 하한도 80에서 멈춘다**: `dungeonFloor(n) = min(1 + 4×(n−1), 80)` — 21번째 신규 던전부터 80 고정.
  해제 후에는 위 표처럼 계속 증가(32번째 125). 해제 전 적이 캐릭터 최대 상한(80)을 넘지 않도록 하기 위함.
- "n번째"는 **그 플레이어가 아직 클리어하지 않은 던전을 도전할 때** 적용된다. 던전 종류별 고정 순번이 아니다
  (플레이어가 순서를 자유롭게 정함).
- **이미 클리어한 던전은 하한 없음**(재도전 시 적 레벨 = 계정 레벨 + 구역 보정).

### 4-4 적 레벨 & 스탯

```
// (해제 전) accountLevel ≤ 80, dungeonFloor ≤ 80 → 기준 레벨 ≤ 80. zoneOffset은 그 위에 더해짐(보스 +4 → 최대 84는 허용, 초안)
enemyLevel   = max(accountLevel, dungeonFloor) + zoneOffset     // 신규 던전
enemyLevel   = accountLevel + zoneOffset                         // 클리어한 던전 재도전
enemyStat(L) = refStat × (1 + (L−1)×0.08) ÷ (1 + (refLevel−1)×0.08)
```

- `refStat`/`refLevel` = CSV의 maxHp·def 등과 levelMin/levelMax 중앙값(**기준값**).
- `zoneOffset`(초안): **잡몹 +0 / 중간보스 +2 / 보스 +4**. 던전끼리 동일. 던전 개성은 패턴·기믹이 만든다.
- 보스는 BossDef의 maxHp/def도 같은 공식으로 `refStat`을 스케일(각 보스 문서의 "스케일링 기준값").

### 4-5 하한 미달 경고

- 계정 레벨 < 던전 하한: 던전 입구에서 **"추천 레벨 N — 현재 적이 N 레벨로 고정되어 어렵습니다"** 경고 팝업 후
  입장 가능(확인 버튼).
- 입장을 막지 않는다. 클리어하면 정상 보상.

### 4-6 보상 스케일 (초안)

- 적 처치 EXP/골드는 적 스탯과 같은 **선형 8%/레벨** 비율로 스케일(기준 레벨 대비).
- 하한 미달로 어려운 던전도 같은 공식을 쓴다(난이도 보상 보너스는 별도 논의).

   완만한 곡선으로 전환 필요(80 부근에서 폭발 방지). 구체 곡선은 미정.

### 엣지 케이스
- **계정 레벨 ≫ 캐릭터 레벨**: 계정만 올리고 캐릭터를 안 키우면 적만 강해진다 — 의도된 동작(문제 풀이 학습으로
  계정 EXP를 얻되 캐릭터 성장도 필요).
- **계정 레벨 ≪ 하한**: 입장은 되지만 적이 하한 레벨로 고정되어 매우 어렵다(경고 표시).
- **해제 후 정수 한계**: 레벨은 int, EXP는 long으로 둔다. 비현실적으로 큰 값은 UI만 클램프.
- **해제 전 상한 도달**: 계정 레벨 80에 도달하면 이후 계정 EXP는 누적만 되고 레벨은 오르지 않는다(해제 시 이월).
- **해제 취소 방지**: 승급 캐릭터 수 조건을 한 번 만족하면 해제 플래그를 저장해 이후 변동에도 유지한다.
- **해제 전 적 레벨 초과**: 보스 +4 보정으로 적 레벨이 80을 넘을 수 있다(최대 84). 캐릭터 최대 상한 80과의 차이는
  의도된 도전 요소(초안, 밸런스 테스트로 조정).
- **재도전 스케일링**: 클리어한 던전 재도전 시 계정 레벨을 따르므로 후반에 쉬워지지 않는다(원 의도).
- **던전 클리어 실패**: 하한 카운트는 **클리어** 기준이라 실패/포기는 영향 없음.
