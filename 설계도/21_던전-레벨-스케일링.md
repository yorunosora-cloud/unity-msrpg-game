# 21. 던전 레벨 스케일링 & 계정 레벨

> **상태**: 사용자와 대화로 핵심 규칙 확정(2026-11). 모든 규칙이 확정되었고(2026-11-21), 수치(EXP 계수 등)는
> 밸런스 테스트로 조정한다. **구현 미착수(설계만).**
> **레벨 상한 정책(2026-11 정정)**: 캐릭터 레벨 상한은 **존재**하며 08 승급(니케 "스페어 바디" 방식)으로 단계적으로
> 올라간다. **최종 랭크까지 승급한 캐릭터가 10명 이상이 되면 레벨 상한이 보유 캐릭터 전체·계정 모두에서 해제**된다.
> 따라서 08 승급은 대부분 유지되고 "상한 해제 조건"만 추가된다(§7).

## 배경

지금까지 던전은 "권장 레벨 lv22-27"처럼 **고정 레벨**로 설계됐다. 이 방식은 플레이어가 던전 순서를
레벨에 맞춰 따라가야 하고, 후반에 앞 던전을 다시 돌면 시시해진다. 사용자는 **플레이어가 원하는
순서로 던전에 도전**할 수 있도록 하되, 완전 스케일링의 약점(레벨업 동기 약화)을 **진입 하한**으로
보완하는 방식을 확정했다.

핵심 원칙: **"막으려는 게 목적이 아니고 성장이 목적이다. 한도에 못 미치면 어려울 뿐이다."**

---

## 1. 목표 / 완료 정의

- 던전 적·보스의 레벨이 **계정 레벨**에 맞춰 결정되고, 고정 권장 레벨 표기가 사라진다.
- 던전 클리어 순서(몇 번째로 새 던전을 깨는가)에 따라 **진입 하한**이 정해지며, 하한 미만이어도
  입장은 가능하고 경고만 표시된다(적이 하한 레벨로 고정되어 어려워짐).
- **계정 레벨**이 신설되어 문제 풀이·던전/보스 클리어·임무/출석으로 오른다. **해제 전 상한 80, 최종 랭크
  승급 캐릭터 10명 이상이면 상한 해제(무제한).**
- **던전별 기준 레벨 대역을 두지 않는다**(2026-11-26): CSV·보스 문서의 수치는 모두 **Lv1 기준 역할별 공통값**(§4-4-bis)이다. 어느 던전을 먼저 가도 같은 역할의 적은 같은 강함이다.

### 4-1-bis 레벨 상한 전역 해제 (신규)

```csharp
public static class LevelCapUnlock
{
    public const int RequiredMaxRankCount = 10;     // 사용자 승인
    public const int PreUnlockCap = 80;             // 해제 전 계정 레벨 상한 = UR 캐릭터 상한
    // 최종 랭크(MaxPromotionRank)까지 승급한 보유 캐릭터 수가 10 이상이면 해제
    public static bool IsUnlocked(IEnumerable<OwnedCharacter> owned)
        => owned.Count(o => o.promotionRank >= PromotionTuning.MaxRank(o.def.rarity)) >= RequiredMaxRankCount;
}
```

- 해제는 **한 번 달성하면 영구**(이후 승급 캐릭터 수가 줄어도 되돌리지 않음 — 플래그 저장 권장).
- 해제 효과: ① 모든 캐릭터의 `LevelCap` 무시 ② 계정 레벨 상한 80 해제 ③ 던전 하한이 80에서 계속 증가.

### 4-2 계정 EXP

| 경로 | 지급 시점 | 비고 |
|------|----------|------|
| 문제 풀이(R&E) | 레벨업/스킬 문제 정답 시 | 학습과 성장 직결 — 이 게임의 핵심 |
| 던전·보스 클리어 | 던전 클리어, 신규 던전 최초 클리어 보너스 | 하한을 넘기 위한 압박과 보상 |
| 일일/주간 임무·출석 | 15, 13번 보상에 계정 EXP 항목 추가 | 꾸준한 플레이 보상 |

**필요 EXP 곡선(확정, A=100·K=1.3 — 밸런스 테스트로 미세 조정)**:

```
levelUpExp(L) = A × L^K     // A = 100, K = 1.3 (확정)
```

- 지수 곡선(`1.45^L`)을 쓰지 않는다 — 고레벨 폭발을 막기 위함(현행 공식은 L=40에서 약 2억, L=80에서 약 5.5×10¹⁴).
- **신규 던전 최초 클리어 보너스(확정)**: 그 시점 **현재 레벨의 필요 EXP 한 번 분량**(= 1레벨 분)을 계정 EXP로 지급한다.
  하한이 4레벨씩 오르는 간격 중 1레벨만 던전이 채우고 나머지는 문제 풀이·임무·일반 보상이 채운다(학습 비중 유지).

### 4-2-bis 캐릭터 레벨업 EXP 곡선 (확정 2026-11-21)

**전 구간을 완만한 다항식으로 교체**(해제 전·후 구분 없이 하나의 곡선, 계정 레벨과 같은 형태·계수):

```
NextExp(L) = 100 × L^1.3      // 캐릭터 · 계정 공통 (A=100, K=1.3 확정, 밸런스 테스트로 미세 조정)
```

| 레벨 | 10 | 20 | 40 | 80 | 120 |
|---|---|---|---|---|---|
| 필요 EXP | 약 2,000 | 약 4,900 | 약 12,000 | 약 29,700 | 약 50,000 |

- 수정 지점: `StatGrowth.NextExp`(캐릭터, `CombatCharacter.ComputeNextExp`가 사용)와 `PlayerStats.GainExp`의 `×1.45`.
  EXP 값은 **`long`** 으로 확장(레벨 해제 후 큰 값 대비).
- 기존 `PlayerStatsTests`는 1.45 곡선 기준 기대값이라 **교체 후 갱신 필요**: 새 곡선에서 Lv1→2는 100(동일),
  Lv2→3은 `100×2^1.3 ≈ 246`이라 Lv3 누적은 약 346이다(현행 테스트의 `GainExp(245)` → Lv3 기대는 깨짐).

### 4-3 진입 하한

```
dungeonFloor(n) = 1 + 4 × (n − 1)     // n = 클리어한 서로 다른 던전 수 + 1
```

| 신규 클리어 순번 | 하한 | | 신규 클리어 순번 | 하한 |
|---|---|---|---|---|
| 1번째 | 1 | | 9번째 | 33 |
| 2번째 | 5 | | 16번째 | 61 |
| 3번째 | 9 | | 24번째 | 93 |
| 4번째 | 13 | | 32번째(예상 마지막) | 125 |

- **해제 전에는 하한도 80에서 멈춘다**: `dungeonFloor(n) = min(1 + 4×(n−1), 80)` — 21번째 신규 던전부터 80 고정.
  해제 후에는 위 표처럼 계속 증가(32번째 125). 해제 전 적이 캐릭터 최대 상한(80)을 넘지 않도록 하기 위함.
- "n번째"는 **그 플레이어가 아직 클리어하지 않은 던전을 도전할 때** 적용된다. 던전 종류별 고정 순번이 아니다
  (플레이어가 순서를 자유롭게 정함).
- **이미 클리어한 던전은 하한 없음**(재도전 시 적 레벨 = 계정 레벨 + 구역 보정).

### 4-4 적 레벨 & 스탯

```
// (해제 전) accountLevel ≤ 80, dungeonFloor ≤ 80 → 기준 레벨 ≤ 80. zoneOffset은 그 위에 더해짐(보스 +4 → 최대 84 허용, 사용자 승인)
enemyLevel   = max(accountLevel, dungeonFloor) + zoneOffset     // 신규 던전
enemyLevel   = accountLevel + zoneOffset                         // 클리어한 던전 재도전
enemyStat(L) = lv1Stat × (1 + (L−1)×0.08)
```

- `lv1Stat` = CSV·BossDef의 maxHp·def 등(**Lv1 기준 값**, §4-4-bis).
- `zoneOffset`(확정): **잡몹 +0 / 중간보스 +2 / 보스 +4**. 던전끼리 동일. 던전 개성은 패턴·기믹이 만든다.
- 보스는 BossDef의 maxHp/def와 패턴 피해·소환물 HP도 같은 공식으로 스케일한다.

### 4-4-bis Lv1 역할별 공통표 (기준 통일은 확정 2026-11-26, 수치는 초안)

던전·대륙에 상관없이 **같은 역할이면 같은 수치**다. 난이도는 ① 진입 순서(하한, §4-3) ② 던전 안 역할 ③ 패턴·기믹으로만 정해진다.

| 역할 | 던전 안 위치 | maxHp | def | EXP | 골드 |
|---|---|---|---|---|---|
| 공통 잡몹 (지상·근접형) | 전 구역 | 70 | 5 | 40 | 10 |
| 공통 잡몹 (공중·원거리형) | 전 구역 | 65 | 4 | 40 | 10 |
| 전용 잡몹 ① | 첫 구역 | 75 | 5 | 45 | 10 |
| 전용 잡몹 ② | 둘째 구역 | 85 | 6 | 46 | 11 |
| 전용 잡몹 ③ | 셋째 구역 | 90 | 6 | 48 | 11 |
| 중간보스 ① (입문) | 첫 구역 | 110 | 7 | 70 | 17 |
| 중간보스 ② (중간) | 둘째 구역 | 120 | 7 | 80 | 19 |
| 중간보스 ③ (최고) | 셋째 구역 | 140 | 8 | 95 | 21 |
| 보스 3페이즈 | — | 650 | 10 | | |
| 보스 4페이즈 | — | 750 | 11 | | |
| 보스 5페이즈 | — | 850 | 12 | | |

- 공통 잡몹은 CSV에서 던전마다 첫 두 행을 지상·원거리 값으로 넣었다(공통이 4종인 원소 주기율표 대성당은 공격 방식으로 배정).
- 순서가 자유인 쌍둥이 구역(이중나선 황궁의 왓슨·크릭 탑)은 두 중간보스 모두 ① 값, 두 보스 모두 4페이즈 값이다.
- **보스 문서의 피해·소환물 HP**: maxHp·def는 위 표 값으로 다시 썼고, 그 밖의 절대 수치는 이전 기준으로 적힌 채 각 문서 상단의 **환산 배율**(×0.32~×0.56)을 곱해 BossDef에 입력한다.
- **예외(제외 확정 2026-11-26)**: 메조리아·수학 진입부의 **유클리드**(maxHp 3000, `EuclidSetup`으로 이미 구현된 단일 스토리 보스)는 **나중에 따로 설계**하므로 이 공통표를 적용하지 않는다.

### 4-5 하한 미달 경고

- 계정 레벨 < 던전 하한: 던전 입구에서 **"추천 레벨 N — 현재 적이 N 레벨로 고정되어 어렵습니다"** 경고 팝업 후
  입장 가능(확인 버튼).
- 입장을 막지 않는다. 클리어하면 정상 보상.

### 4-6 보상 스케일 (확정)

- 적 처치 EXP/골드는 적 스탯과 같은 **선형 8%/레벨** 비율로 스케일(Lv1 값 기준).
- 하한 미달로 어려운 던전도 같은 공식을 쓴다. **하한 미달 난이도 보너스는 두지 않는다**(확정 — 보너스를 노린
  낮은 레벨 고난도 돌기 악용 방지, 보상은 강해진 적 비율로 자연스럽게 증가).

### 4-7 일일·주간 임무(15번) 적 처치 목표 기준 (확정)

적 레벨이 계정 레벨에 스케일링되어 "플레이어 레벨대 필터"는 폐기한다. 대신:
- 적 처치 목표의 `contextId`는 **플레이어가 클리어한 던전의 지역(region) 중 무작위 1곳**에서 뽑는다
  (`AccountProgress.clearedDungeons` ↔ 17번 `EnemyCatalog.ByRegion`). 이미 깬 곳이라 달성 가능하고, 적 레벨은 계정에
  맞춰 자동 적절.
- **초반 폴백**: 클리어한 던전이 없으면 **진입 지역의 기본 적 고정 풀**(메조리아 외곽/첫 대륙 진입 지역의 적 목록)에서
  뽑는다. 클리어 이력이 생기면 클리어 던전 풀로 자동 전환.
- 15번 문서 결정 #3과 17번 `LevelBandId` 주석에 동일 내용 반영.

### 엣지 케이스
- **계정 레벨 ≫ 캐릭터 레벨**: 계정만 올리고 캐릭터를 안 키우면 적만 강해진다 — 의도된 동작(문제 풀이 학습으로
  계정 EXP를 얻되 캐릭터 성장도 필요).
- **계정 레벨 ≪ 하한**: 입장은 되지만 적이 하한 레벨로 고정되어 매우 어렵다(경고 표시).
- **해제 후 정수 한계**: 레벨은 int, EXP는 long으로 둔다. 비현실적으로 큰 값은 UI만 클램프.
- **해제 전 상한 도달**: 계정 레벨 80에 도달하면 이후 계정 EXP는 누적만 되고 레벨은 오르지 않는다(해제 시 이월).
- **해제 취소 방지**: 승급 캐릭터 수 조건을 한 번 만족하면 해제 플래그를 저장해 이후 변동에도 유지한다.
- **해제 전 적 레벨 초과**: 보스 +4 보정으로 적 레벨이 80을 넘을 수 있다(최대 84). 캐릭터 최대 상한 80과의 차이는
  의도된 도전 요소(사용자 승인, 밸런스 테스트로 조정).
- **재도전 스케일링**: 클리어한 던전 재도전 시 계정 레벨을 따르므로 후반에 쉬워지지 않는다(원 의도).
- **던전 클리어 실패**: 하한 카운트는 **클리어** 기준이라 실패/포기는 영향 없음.
