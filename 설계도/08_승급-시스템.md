# 08. 승급 시스템

---

## 세계관 맥락

- `게임 시스템 설계.md §2-3`은 **"등급 = 성장 상한"**(등급은 전투력이 아니라 레벨·돌파 한계)으로 규정한다. N도 초반엔 UR과 비슷한 전투력으로 시작하되, 더 키울 수 있는 한계가 등급으로 정해진다.
- `게임 시스템 설계.md §4-2`는 **돌파(限界突破)** — 레벨 상한에 도달하면 재료로 상한을 해제 — 를 등급별 횟수(N2/R2/SR3/SSR3/UR4)로 설계했다.
- 서사적으로 승급은 **"개념의 심화"** 다. 같은 개념을 반복 학습(중복 획득 = dupes)하고 그 과목의 결정(개념 조각)을 투입할수록 그 개념을 더 깊이 다룰 수 있게 된다 — 교육 RPG의 "반복 학습 → 숙련" 메타포. 심화의 결과로 **그 개념의 새로운 응용(신규 스킬)** 이 열린다.
- **이 설계도는 `promotionRank` 하나로 레벨 상한 해제(돌파)·스탯 상한 확장·매 랭크 신규 스킬 해금을 통합한 승급 시스템의 데이터·로직·UI 전체를 다룬다.**

---

## 1. 목표 / 완료 정의

1. **승급 1사이클**: 도감 상세 뷰에서 캐릭터를 선택 → dupes·결정이 충분하면 **[승급]** 버튼 활성 → 클릭 시 재화 차감 + `promotionRank++` + 별 표시 갱신 + 즉시 레벨 상한·스탯 상한 상승.
2. **레벨 상한 통합**: `promotionRank`에 따라 레벨 상한이 단계적으로 상승하며, 최대 랭크의 상한은 기존 `Rarity.LevelCap`(N40/R50/SR60/SSR70/UR80)과 정확히 일치한다.
3. **스탯 상한 확장**: 승급 랭크당 전 스탯에 누적 %보너스가 붙는다(스탯 캡 확장). 레벨 성장 위에 곱해진다.
4. **매 랭크 신규 스킬 해금**: 승급으로 랭크 N 도달 시 `CharacterDef.promotionSkillIds[N-1]`의 스킬이 `unlockedSkillIds`에 추가되어 스킬바에서 즉시 발동 가능해진다.
5. **재화 소비**: 승급 N단계는 dupes N개 + 과목 결정(base×N)을 소비하며, 부족 시 버튼 비활성 + 사유 표시.
6. **영속화**: `promotionRank`와 해금 스킬이 PlayFab 세이브에 자동 반영되어 재로그인 후에도 유지된다.
7. **데이터 주도 튜닝**: 등급별 최대 랭크·레벨 상한·스탯 보너스·비용이 모두 `PromotionTuning` 한 곳에서, 캐릭터별 해금 스킬은 `CharacterDef.promotionSkillIds` 한 곳에서 조정된다.

### 확정된 설계 결정
| # | 결정 | 근거 |
|---|------|------|
| 1 | 승급 = `OwnedCharacter.promotionRank`, `Rarity`는 불변 | §2-3 "등급=성장상한, 고정". 개체별 승급(원신 명함/명조식). 서사 충돌 회피 |
| 2 | 돌파를 별도 구현하지 않고 `promotionRank`에 통합 | YAGNI. 한 축이 레벨 상한+스탯 상한 동시 관리, 설계도 1개로 완결 |
| 3 | 재화 = dupes(주) + 과목 결정(보완) | 두 미사용 시스템 동시 활용. 애착(그 캐릭터 또 뽑기)+비공자 보완(결정) 균형 |
| 4 | 최종 랭크 레벨 상한 = 기존 `Rarity.LevelCap` | 기존 상수와 정합, §4-2 돌파표와 일치 |
| 5 | 튜닝값은 `PromotionTuning` 정적 테이블 1곳 집중 | 밸런싱 반복을 코드 흩어짐 없이 |
| 6 | UI는 도감 상세 뷰(`CodexDetailBuilder`)에 섹션 추가 | 기존 캐릭터 상세 진입점 재사용, 신규 패널 0 |
| 7 | 해금 스킬 = `CharacterDef.skills[]` 중 id를 `promotionSkillIds[]`로 명시 매핑 | 기존 스킬·해금 시스템(`unlockedSkillIds`/`IsUnlocked`) 재사용, 신규 발동 코드 0 |

### 3-2. 튜닝 테이블 — `PromotionTuning` (신규)

**`Scripts/Meta/PromotionTuning.cs`** (신규):
```csharp
using UnityEngine;

/// <summary>승급 밸런싱 테이블. 등급별 최대 랭크·레벨 상한·스탯 보너스·비용을 한 곳에서 관리.</summary>
public static class PromotionTuning
{
    public static int MaxRank(Rarity r) => r switch {
        Rarity.N => 2, Rarity.R => 2, Rarity.SR => 3, Rarity.SSR => 3, Rarity.UR => 4, _ => 0,
    };

    static int BaseLevelCap(Rarity r) => r switch {
        Rarity.N => 30, Rarity.R => 40, Rarity.SR => 45, Rarity.SSR => 55, Rarity.UR => 60, _ => 30,
    };
    public const int LevelStep = 5;

    public static int LevelCapAt(Rarity r, int rank) {
        rank = Mathf.Clamp(rank, 0, MaxRank(r));
        return BaseLevelCap(r) + rank * LevelStep;
    }

    public static float StatBonusPerRank(Rarity r) => r switch {
        Rarity.N => 0.06f, Rarity.R => 0.06f, Rarity.SR => 0.08f, Rarity.SSR => 0.08f, Rarity.UR => 0.10f, _ => 0f,
    };
    public static float StatMultiplier(Rarity r, int rank) =>
        1f + Mathf.Clamp(rank, 0, MaxRank(r)) * StatBonusPerRank(r);

    public static int DupesCost(int targetRank) => Mathf.Max(1, targetRank);

    static int CrystalBase(Rarity r) => r switch {
        Rarity.N => 8, Rarity.R => 15, Rarity.SR => 30, Rarity.SSR => 60, Rarity.UR => 120, _ => 0,
    };
    public static int CrystalCost(Rarity r, int targetRank) => CrystalBase(r) * Mathf.Max(1, targetRank);
}
```

**튜닝 요약표**:

| 등급 | 최대랭크 | rank0 상한 | 최종 상한 | 랭크당 스탯 | 결정 base |
|------|--------|-----------|----------|-----------|----------|
| N | 2 | 30 | 40 | +6% | 8 |
| R | 2 | 40 | 50 | +6% | 15 |
| SR | 3 | 45 | 60 | +8% | 30 |
| SSR | 3 | 55 | 70 | +8% | 60 |
| UR | 4 | 60 | 80 | +10% | 120 |

> 최종 상한(BaseLevelCap + MaxRank×5) 검산: N 30+10=40, R 40+10=50, SR 45+15=60, SSR 55+15=70, UR 60+20=80. `Rarity.LevelCap()`과 전 등급 일치. ✔

```csharp
/// <summary>승급 랭크까지 반영한 최종 스탯. 레벨 성장 × 승급 보너스.</summary>
public static CharacterStats ComputeStats(CharacterDef def, int level, int promotionRank)
{
    float m = (1f + (level - 1) * Growth) * PromotionTuning.StatMultiplier(def.rarity, promotionRank);
    var b = def.baseStats;
    return new CharacterStats {
        hp  = Mathf.RoundToInt(b.hp  * m),
        atk = Mathf.RoundToInt(b.atk * m),
        def = Mathf.RoundToInt(b.def * m),
        spd = Mathf.RoundToInt(b.spd * m),
        mp  = Mathf.RoundToInt(b.mp  * m),
    };
}

/// <summary>승급 랭크 반영 레벨 상한.</summary>
public static int LevelCap(Rarity rarity, int promotionRank) => rarity.LevelCapAt(promotionRank);
```

### 3-5. 승급 서비스 — `PromotionService.cs` (신규)

**`Scripts/Meta/PromotionService.cs`** (신규):
```csharp
using UnityEngine;

/// <summary>승급 가능 여부 판정 및 실행. dupes + 과목 결정을 소비해 promotionRank를 올린다.</summary>
public static class PromotionService
{
    public struct Cost { public int dupes; public CrystalKind crystal; public int crystalAmount; }

    public static Cost NextCost(CharacterDef def, OwnedCharacter owned)
    {
        int target = owned.promotionRank + 1;
        if (target > def.rarity.MaxPromotionRank())
            return new Cost { dupes = -1, crystalAmount = -1 };
        return new Cost {
            dupes         = PromotionTuning.DupesCost(target),
            crystal       = CrystalCatalog.KindFor(def) ?? default,
            crystalAmount = PromotionTuning.CrystalCost(def.rarity, target),
        };
    }

    public static bool CanPromote(CharacterDef def, OwnedCharacter owned, out string reason)
    {
        if (owned.promotionRank >= def.rarity.MaxPromotionRank()) { reason = "최대 승급"; return false; }
        var c = NextCost(def, owned);
        if (owned.dupes < c.dupes) { reason = $"중복 부족 ({owned.dupes}/{c.dupes})"; return false; }
        var wallet = MetaState.Crystals;   // 확인 완료 (2026-07-07 대조)
        if (wallet == null || wallet.Get(c.crystal) < c.crystalAmount) {
            reason = $"{CrystalCatalog.DisplayName(c.crystal)} 부족"; return false;
        }
        reason = null; return true;
    }

    /// <summary>다음 승급에서 해금될 스킬. null이면 그 랭크는 스킬 없이 승급.</summary>
    public static SkillDef NextUnlockSkill(CharacterDef def, OwnedCharacter owned)
    {
        int idx = owned.promotionRank;   // rank N 도달 시 promotionSkillIds[N-1] → 현재 rank가 인덱스
        if (def.promotionSkillIds == null || idx >= def.promotionSkillIds.Length) return null;
        string sid = def.promotionSkillIds[idx];
        if (string.IsNullOrEmpty(sid) || def.skills == null) return null;
        foreach (var s in def.skills) if (s != null && s.id == sid) return s;
        return null;
    }

    /// <summary>승급 실행. 성공 시 재화 차감 + promotionRank++ + 스킬 해금 + Roster.OnChanged 발행.</summary>
    public static bool Promote(CharacterDef def, OwnedCharacter owned)
    {
        if (!CanPromote(def, owned, out _)) return false;
        var c = NextCost(def, owned);
        var newSkill = NextUnlockSkill(def, owned);   // rank++ 전에 조회
        if (!MetaState.Crystals.TrySpend(c.crystal, c.crystalAmount)) return false;
        owned.dupes -= c.dupes;
        owned.promotionRank += 1;
        if (newSkill != null) {
            owned.unlockedSkillIds ??= new System.Collections.Generic.List<string>();
            if (!owned.unlockedSkillIds.Contains(newSkill.id))
                owned.unlockedSkillIds.Add(newSkill.id);
        }
        MetaState.Roster.NotifyChanged();
        return true;
    }
}
```
> **소비 순서**: 결정 `TrySpend`를 먼저 — 실패 시 dupes·스킬을 건드리지 않음(원자성).
> **스킬 해금은 `OwnedCharacter` 직접 조작**: 허브에선 `CombatCharacter` 인스턴스가 없을 수 있다. 다음 전투 진입 시 `IsUnlocked`가 자동 반영.

**`Backend/PromotionSection.cs`** (신규, Assembly-CSharp):
```csharp
using UnityEngine;
using UnityEngine.UI;
using TMPro;

/// <summary>도감 상세 뷰 — 승급 섹션 (별 표시·비용·해금 미리보기·[승급] 버튼).</summary>
public static class PromotionSection
{
    public static void Build(RectTransform parent, CharacterDef def, OwnedCharacter owned)
    {
        int max = def.rarity.MaxPromotionRank();
        // 헤더: "승급  ★★☆☆ (2/4)"
        string stars = new string('★', owned.promotionRank) + new string('☆', max - owned.promotionRank);
        // … (UITheme로 라벨/배경 생성)

        if (owned.promotionRank >= max) {
            // "최대 승급 달성" 라벨, 버튼 없음
            return;
        }

        var cost = PromotionService.NextCost(def, owned);
        // 비용 라벨: "중복 {owned.dupes}/{cost.dupes} · 〈결정명〉 {보유}/{cost.crystalAmount}"
        var nextSkill = PromotionService.NextUnlockSkill(def, owned);
        // 해금 미리보기: "다음 해금: 〈스킬명〉" (nextSkill != null 시만)
        bool can = PromotionService.CanPromote(def, owned, out string reason);

        // [승급] 버튼 — can이면 활성, 아니면 비활성 + reason 표시
        // onClick: PromotionService.Promote(def, owned) 후 상세 뷰 재빌드
    }
}
```
> 미해금 스킬을 "🔒 승급 N 해금"으로 흐리게 미리 보여주면 목표감이 커진다(옵션). 승급 후 `CodexDetailBuilder.Build`를 재호출해 상세 뷰를 갱신한다 — `CollectionPanel.ShowDetail`을 콜백으로 받는 방식이 깔끔.

**`Backend/CodexCardBuilder.cs` 수정(옵션)** — 보유 카드 우하단에 `promotionRank`만큼 작은 ★ 표시.

## 6. 엣지 케이스 / 주의점

| 상황 | 처리 방식 |
|------|----------|
| 구 세이브(promotionRank 필드 없음) | `JsonUtility` 역직렬화 시 0 = 미승급. rank0 레벨 상한이 기존보다 낮아지지만, 라이브였던 적 없으므로 허용. 상한 초과 레벨 캐릭터는 다음 GainExp부터 새 상한 적용(강제 하향 없음) |
| 최대 랭크 도달 | `CanPromote` false + "최대 승급" 라벨, 버튼 숨김 |
| 결정 차감 후 dupes 차감 | `TrySpend`(실패 가능) **먼저**, dupes(실패 없음) 나중 — 원자성 보장 |
| 결정 종류 없음(`KindFor` null) | 가챠 캐릭터는 과목 보유 가정. null이면 `CanPromote` false(방어) |
| 승급 중 전투 진행 | 승급은 메조리아 허브(도감)에서만 — 전투 중 변경 없음 |
| 승급 직후 상세 뷰 미갱신 | `Promote` 성공 시 상세 컨텐츠 클리어 후 재빌드(콜백) |
| `ComputeStats` 빈번 호출 | 현 getter 빈도에서 문제 없으면 캐싱 안 함(YAGNI) |
| EditMode 테스트 격리 | `MetaState`/CrystalWallet 의존 → 순수 함수(`Tuning`/`NextCost`/`NextUnlockSkill`) 위주 검증 |
| dupes를 결정으로도 적립(가챠 중복) | 중복 1회 = dupes+1 **and** 결정 지급(기존 로직 유지). 이중 적립이 이중 비용을 상쇄 — 의도된 균형 |
| 6슬롯 한계 | `skills[]`는 U/I/O/H/J/K 6개. base + 승급 스킬(최대 UR 4) + 문제풀이 해금 스킬 합이 6 초과 불가 — 시드 제작 책임. `promotionSkillIds`는 반드시 `skills[]` 내 id |
| 해금 스킬 id가 `skills[]`에 없음 | `NextUnlockSkill`이 null → 그 랭크는 스킬 없이 승급(스탯/레벨 상한만). 시드 오류 방어 |
| 이미 해금된 스킬(문제풀이로 먼저) | `unlockedSkillIds.Contains` 체크로 중복 추가 안 함 — 승급은 멱등 |
| 승급 직후 스킬바 미반영 | 승급은 허브에서 발생, 다음 전투 진입 시 `IsUnlocked` 재평가로 자동 반영 |
